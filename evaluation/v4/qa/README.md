# 비서 QA 도구(실제 서비스와 같은 환경)

- 사람 역할(질문 · 단추 누르기 · 채점)은 Claude Code QA 에이전트가 해요. 그래서 질문 쪽 API 비용은 0이에요.
- 비서는 실제와 같아요: 같은 코드 · 같은 설정(LLM 모드 · 지시문 · 비용 상한 운영 기본값) · 같은 API(8050) · 같은 worker.
- 돈이 드는 곳은 비서 쪽뿐이에요: 비서 턴, 먼저 말 걸기 판정 · 문장, 기억 뽑기, 업체 브리핑 한 줄. 모두 사용자 하루 $0.40 · 서비스 하루 $5 상한을 지나고, 90%를 넘으면 무료 모드로 떨어져요(`say` 머리에 '무료 모드'로 보여요).

## 1. 리드가 실제 QA 전에 할 일
1. 서버 · worker를 끈 상태에서 DB를 새로 만들어요: `bash evaluation/v4/qa/make_db.sh qa`
   - `mitjip_v4`(미리보기)는 읽기만 해요(pg_dump → 새 DB, Alembic head까지).
   - 복사본의 비용 장부(`llm_usage`)와 Redis db 13을 비우고, 미리보기 파일 폴더를 QA 폴더로 복사하고, 시간 당기기 상태를 지워요.
2. API: `bash .claude/run-qa-api.sh` (포트 8050, DB `mitjip_qa`, Redis 13, LLM 모드)
3. worker: `bash .claude/run-qa-worker.sh` (같은 DB · Redis · 모드)
4. 비밀 폴더 적기(체크아웃마다 한 번): `bash evaluation/v4/qa/qa.sh init --secrets <scratchpad 폴더>`
   - 그 폴더의 `e2e_accounts.json`(업체 '믿집시험도배' = 키 `vendor`)을 읽고, 새 QA 계정은 `qa_accounts.json`에 써요.
5. 확인: `curl http://127.0.0.1:8050/health/ready`, 첫 `say`의 머리가 'LLM 모드'인지.

- 도구를 고칠 때는 같은 스크립트에 `dev`를 붙여요: `make_db.sh dev` · `run-qa-api.sh dev` · `run-qa-worker.sh dev` → `mitjip_qa_dev` · 8051 · Redis 6 · 무료 모드(유료 0회). 명령에는 `--api http://127.0.0.1:8051`.
- 코드는 스크립트가 있는 체크아웃의 `backend`예요. 통합 브랜치 코드로 QA하려면 그 worktree에서 띄워요.

## 2. 쓰는 법
```bash
Q="bash evaluation/v4/qa/qa.sh --tag <태그>"   # 기본 API 8050. 태그는 기록 폴더 이름(영어 소문자 · 숫자 · 하이픈)
$Q new c1 --persona "맞벌이 부부" --sgg 노원구 --pyeong 32 --occupied no --start 2026-12-21
$Q say c1 "도배 업체 추천해 주세요"
$Q press c1 "visit_request:v1,v3"
$Q approve c1 1a2b3c4d
```
- Bash 도구는 셸 변수를 다음 호출로 넘기지 않아요. 명령마다 `--tag`를 같이 써요.
- 시간 당기기(`tick`)는 하루에 30~40초쯤 걸려요. Bash 시간 제한을 넉넉히(600000) 둬요.

### 고객
| 명령 | 하는 일 |
| --- | --- |
| `new <키> --persona <이름> [집 칸]` | 화면과 같은 길로 가입해요: 손님 표준견적서(`POST /guest/standard`) → 가입 → 공사 만들기(`POST /projects` + 멱등 키). 이메일 `qa-<태그>-<키>@mitjip.test`, 비밀번호는 무작위로 만들어 비밀 파일에만 둬요. 집 칸: `--sgg`(기본 노원구) `--pyeong`(32) 또는 `--area`·`--basis` · `--occupied yes/no` · `--grade basic/economy`(실크 · 합지) · `--scope full/partial --spaces` · `--rooms` · `--budget`(만 원) · `--start` · `--demolition full/partial/none` |
| `say <키> "<말>"` | 비서 턴(SSE)을 끝까지 받아 보여요: 글 묶음과 출처(믿집 계산 · AI 답변 · 믿집 안내) · 카드 kind와 핵심 값 · 단추 · 승인 카드(짧은 id · 제목 · 요약 · 상태) · 작업 줄 · 다음에 물을 말 · 칩 |
| `say <키> --pick <n>` | 지난 턴 '다음에 물을 말' n번을 눌러요(먼저 말 건 줄이면 화면처럼 열기를 알리고 그 말을 보내요) |
| `press <키> "<고르기>"` | 카드 단추. 화면과 같은 요청(카드 id + `context.choice` + 단추 말)이에요. `visit_request:v1,v2[,r1]` · `visit_slot:s2` · `vendor_confirm:m1` · `dates_accept:p1` · `delay_accept:p1` · `extra_answer:x1[,reject · ask]` · `demolition:full`. 여럿을 띄어 쓰면 한 턴에 목록으로 보내요(도배 전 점검 `prework.floor:done prework.electric:todo`, 말은 화면처럼 '앞 공사 답: …') |
| `approve · reject <키> <id>` | 승인 카드 누르기 · 거절(화면처럼 본 판 `seen`과 누름 키를 같이 보내요). id는 출력의 짧은 id(뒤 8자리)나 앞 · 뒤 어느 쪽 일부든 돼요 |
| `nudge <키> open · dismiss <id>` | 먼저 말 건 줄 [해 볼게요] · [괜찮아요] |
| `feed <키> [--full] [--pages n]` | 대화 기록(먼저 말 건 줄 · 완료 표시 포함) |
| `board <키>` | 공사 한눈에(단계 띠 · 돈 · 업체 줄 · 기간 · 기억) + 오늘 정할 일 |
| `actions <키> [--all]` | 승인 카드 목록(기본은 기다리는 것만) |
| `bell <키 · 업체> [--read n]` | 종 알림, n번 읽음 |
| `memory <키>` | 비서가 기억한 것(근거 고객 말) |

### 업체
- 업체는 키(`vendor` = 믿집시험도배) · 상호(결도배 · 마루와벽 · 믿집시험도배) · 이메일로 불러요.
- 믿집시험도배는 비밀번호로 로그인해요. 비밀번호를 모르는 업체(결도배 · 마루와벽)는 로그인과 같은 세션 함수(`auth.service.start_session`)로 세션을 만들어 똑같이 HTTP로 보내요(비밀번호 확인만 건너뜀).

| 명령 | 하는 일(v3 업체 화면과 같은 API) |
| --- | --- |
| `vendor <업체> window <고객 키> [--start --end --exclude --instant yes/no]` | 기간 답하기. 기본은 고객 희망 기간(내일부터, 14일), 바로 확정은 업체 기본값 |
| `vendor <업체> decline <고객 키> [--code full/out_of_area/other --note]` | 못 받아요 |
| `vendor <업체> accept <고객 키>` | 고객이 고른 반나절 수락 |
| `vendor <업체> quote <고객 키> [--amount 3300000 --vat included --days 3 --valid --spec "벽지 사양" --warranty 12 --removal --waste]` | 작은 PDF 올리기 → 임시 저장 → 보내기 |
| `vendor <업체> dates <고객 키> [--start 날짜 · --days-list a,b --crew]` | 공사 날짜 보내기. 견적서 공사 기간만큼 일하는 날을 골라요. 고객이 날짜 바꾸기를 요청했으면 그 요청에 답하는 새 날짜(kind change · request_id)예요 |
| `vendor <업체> extra <고객 키> --amount 150000 --title "…" --reason "…" [--vat excluded]` | 추가 금액 올리기 |
| `vendor <업체> done <고객 키> [--note]` | 공사 끝냈어요(마지막 공사일부터, 4절) |
| `vendor <업체> job · brief · checklist · seen <고객 키>` | 공사 화면 · 요청 브리핑(기간 답하기 제안이 생겨요) · 견적서 체크리스트 · 요청 열어 봄 |
| `vendor <업체> today · feed · actions` | 업체 비서 화면: 오늘 할 일 · 대화 기록 · 열린 승인 카드 |
| `vsay <업체> "<말>" [--visit <고객 키>] [--pick n]` | 업체 비서 턴(보던 요청을 고객 키로) |
| `vpress <업체> "<고르기>" [--visit <고객 키>]` | `window_answer:w1` · `decline:full` · `dates:d1,n1`(오늘 할 일 단추) |
| `vapprove · vreject <업체> <id>` | 업체 승인 카드 |

### 시간 · 비용
| 명령 | 하는 일 |
| --- | --- |
| `tick <시간> [--every h]` | 시간 당기기(`2d` · `3h` · `1d12h` · `30m`). '지금 + 누적'까지 매시간 5분(worker의 hourly 때)마다 기한 일(`app/run_due.py`와 같음) → `assistant_hourly` → `assistant_sweep`를 차례로 돌려요. 긴 jump는 `--every 6`으로 성기게 |
| `tick 0` | 시간은 그대로 정리만 한 번(worker가 2분 안에 할 먼저 말 걸기를 바로 보고 싶을 때) |
| `clock` | 그 DB의 가상 시각 |
| `cost` | 비용 장부 합(목적 · 모델 · 계정별). make_db가 복사 때 장부를 비워서 QA 비용만 나와요 |

## 3. QA 규칙
- 한 계정 한 대화씩: 고객 키 하나는 에이전트 하나만 써요. 명령이 끝난 뒤 다음 명령을 보내요(같은 대화에 겹치면 409 turn_running).
- 업체 계정은 여럿이 같이 써요(업체 비서 대화는 업체마다 하나). `vsay` · `vpress`는 한 번에 한 에이전트만 해요.
- 승인 카드는 사람이 하듯 눌러요: 요약(업체 · 금액 · 날짜 · 판)을 읽고 페르소나에 맞을 때만 `approve`. 틀리면 `reject`하거나 말로 고쳐 달라고 해요. 이름표(v1 · s2 · m1 · p1 · x1 · w1 · n1)는 그 대화의 카드에 나온 것만 써요.
- 카드에 단추가 없거나 이상하면 누르지 말고 채점표에 적어요(재현 명령과 함께).
- 업체 사건(업체 답 · 견적서 · 날짜 · 추가 금액 · 공사 끝)은 시나리오 대본대로 `vendor`로 만들어요. 먼저 말 걸기는 worker가 2분 안에 보내요. 비서가 스스로 챙기는지 보려면 고객이 묻기 전에 `feed` · `bell`부터 봐요.
- 비밀: 비밀번호 · 세션 · `.env` 값은 비밀 폴더에만 있어요. 출력 · 보고 · 기록에 넣지 않아요.
- 기록: `runs/<태그>/<키>/log.jsonl`(명령마다 한 줄, 턴은 원본 SSE 이벤트 전부) · `state.json`(공사 id · 본 카드). 업체는 `runs/<태그>/_v-<상호>/`. 저장소에는 올라가지 않아요(`evaluation/v4/.gitignore`).

## 4. 시간 당기기의 한계
- API · 화면 · 승인 실행은 실제 시각을 써요. 당긴 시각은 `tick`(기한 일 · hourly · sweep)과 `vendor done`에만 적용돼요.
- `tick`은 그 DB 전체에 적용돼요(다른 에이전트의 승인 카드 만료 · 기한 일 · 먼저 말 걸기도 같이 앞당겨져요). 시간이 필요한 시나리오는 리드가 순서를 정해 한 번에 한 에이전트만 해요. 누적 시각은 `runs/clock-<DB>.json`이고 `make_db.sh`가 지워요.
- worker는 실제 시각으로 돌아요. 시간을 당긴 뒤 생긴 사건을 worker가 먼저 집으면 카드 기한 · 보낸 때가 실제 시각 기준이라, 다음 `tick`에서 바로 닫힐 수 있어요. 업체 사건 직후 `tick 0`을 돌리면 가상 시각으로 만들어져요.
- QA r2 t1에서 더 본 것
  - 알림(사건)은 실제 시각으로 찍혀서, 48시간 넘게 당긴 뒤엔 `tick 0`이 업체 사건을 못 보고 실제 worker가 실제 시각으로 평가해요.
  - 실제 worker의 정리(sweep)는 실제 오늘 기준으로 공사 전날 줄을 몇 분 안에 '완료'로 닫을 수 있어요.
  - 업체 '끝냈어요'를 올린 때도 실제 시각이라, 4일 넘게 당긴 뒤 올리면 다음 `tick`에서 3일 전 알림과 자동 끝이 바로 돌아요. 확인 카드를 먼저 누르거나 당기는 양을 줄여요.
  - 대화 턴이 만든 승인 카드의 기한은 실제 시각 + 3일이라, 다음 `tick` 전에 눌러요.
- 한 시간 단위로 끊어 돌려요. `--every`를 크게 하면 그 사이 시간 트리거(전날 10시 준비물 · 밤 9시 미룸 등)가 늦게 잡히거나 건너뛸 수 있어요.
- `vendor done`: API는 실제 오늘이라 마지막 공사일 전이면 409(too_early)예요. 시간을 당겼으면 같은 service 함수(`schedule.service.finish`)를 가상 오늘로 불러요(끝낸 날 = 가상 오늘).
- 복사해 온 미리보기 사용자의 기한 일 · 먼저 말 걸기도 같은 DB라 함께 돌아요(LLM 모드면 판정 · 문장에 비용이 조금 들어요).
