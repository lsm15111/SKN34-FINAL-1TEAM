# 시공일지 전처리 규칙

- 원본: `시공일지(공유금지).pdf`, 218쪽, 글자 층 없는 스캔본, PDF 한 쪽 = 책 펼침면 2쪽
- 원본 SHA-256: `65eced5777b0bbc3cda2c8763c2bb8b652934531607046a238711b818b2a5571`
- 원본 PDF는 저장소 밖에, 이미지·쪽 JSON·작업 중간 파일은 `data/local/sigong_ilji/`(Git 제외)에 둔다. 최종 CSV는 `data/local/sigong_ilji_rag.csv`에 보관한다. 원본과 본문을 담은 가공 결과는 모두 공유 금지이며 저장소에 올리지 않는다. 가이드북 CSV와의 구분 및 적재 규칙은 [기준 데이터 안내](../../docs/reference-data.md#상담-지식-자료-v2)를 따른다.
- 스크립트는 작업 폴더에서 `python -I ../../sigong_ilji/tools/<스크립트>`로 돌린다. `render.py`만 `pymupdf`가 필요하다(백엔드 의존성 아님, 따로 설치)
- 기존 코드(`knowledge/sources.py` · `json_csv.py` · `data_ingest.py`)는 바꾸지 않음

## 흐름

1~5의 읽기 작업은 `data/local/sigong_ilji/` 폴더를 만든 뒤 그 안에서 진행한다. CSV 변환과 적재는 아래에 명시한 대로 `backend/`에서 실행한다.

1. `uv run --with pymupdf python -I ../../sigong_ilji/tools/render.py "<원본 PDF 절대경로>" .` → `thumb/`(쪽 지도용 축소판) · `img/pNNNL.png`, `img/pNNNR.png`(220dpi 반쪽).
2. 쪽 지도 → `map.json`: `{"7": {"part": "PART 1 <장 제목>", "q": "Q2 <질문 제목>", "text": true}}`
3. 1차 읽기 → `a/pNNN.json`, 2차 읽기(같은 규칙, 따로) → `b/pNNN.json`
4. `python -I ../../sigong_ilji/tools/diff.py a b diff.md` → 어긋난 곳만 300dpi로 다시 보고 `a/`를 고침
5. `python -I ../../sigong_ilji/tools/merge.py a sigong_ilji.json ../../sigong_ilji/joins.json`으로 쪽 JSON을 합친다.
   - `joins.json`: 쪽 경계에서 끊긴 조각을 잇는 쪽과 사이 글자(`""` 붙임 · `" "` 띄움 · `"\n"` 줄바꿈). 이 파일이 있어야 같은 CSV가 다시 나온다
   - 합친 조각에는 양쪽 원본 쪽 번호를 남긴다. 한쪽이 사례이거나 합친 본문에서 금액이 검출되면 결과도 `cases`로 둔다.
   - 합쳐져 없어진 뒤쪽 조각의 번호는 빈 번호로 남긴다. 다른 조각의 번호를 당겨 바꾸지 않는다.
   - 합친 뒤 `backend/`에서 `uv run python -m app.knowledge.json_csv ../data/local/sigong_ilji/sigong_ilji.json ../data/local/sigong_ilji_rag.csv`로 변환한다. 결과 CSV는 로컬에만 보관한다.
6. 적재: 마이그레이션이 적용된 로컬 DB의 `DATABASE_URL`을 설정한 뒤 `backend/`에서 `uv run python -m app.data_ingest load --directory ../data/local --dataset sigong_ilji_rag --execute`를 실행한다. 적재만으로 검색에 활성화되지는 않는다. 기존 `14_sigong_ilji_rag` 적재본이 있으면 중복 활성화를 피하도록 [기준 데이터 사용 안내](../../docs/reference-data.md#상담-지식-자료-v2)를 확인한다. `embed --execute`는 새 본문을 외부 API로 보내므로 공유 금지 자료에 실행하지 않는다.

## 쪽 JSON (`a/pNNN.json`)

```json
{"page": 7, "chunks": [
  {"doc": "book | cases", "sec": "Q2 … > 소제목", "text": "[Q2 … > 소제목]\n본문",
   "trades": [], "topics": ["budget"], "hints": ["고객 말투 질문 1~2개"]}
]}
```

- `text`가 없는 쪽(사진뿐 · 장 표지)은 파일을 만들지 않음
- 번호 · id는 `merge.py`가 매김: `K6000 + 쪽×50 + 순번`, `sigong-p007-03`. 한 쪽 49조각까지

## 청크 규칙

- 소제목(■ · 굵은 제목) 하나 = 청크 하나. 800자 넘으면 문단 경계에서 나눔
- `text` 첫 줄은 `[Q 제목 > 소제목]` 문맥 머리, 이어서 원문 그대로(요약 · 의역 금지)
- 펼침면 왼쪽 → 오른쪽, 쪽 안에서 왼쪽 단 끝까지 → 오른쪽 단
- 표: 행마다 `- 열: 값 | 열: 값`, 표 제목 · 각주(*) 포함
- 체크리스트: 항목마다 `- 항목: 설명`. 빈 줄 · 빈칸 쓰는 자리는 뺌. `topics`에 `checklist`
- 쪽 머리 꼬리표(책의 코너 이름) · 쪽 번호 · 사진 · 장식은 뺌. 뜻 있는 사진 설명만 남김
- 쪽 파일에는 그 쪽 글만 넣음. 앞 쪽에서 이어진 글은 앞 쪽 이미지에서 소제목을 확인해 같은 `sec`를 씀(1차 · 2차 비교가 쪽 단위라서)
- 문맥 머리 · `sec`의 Q 제목은 `map.json`의 `q`. 펼침면 안에서 Q가 바뀌면(`note`의 "왼쪽은 Qn") 왼쪽 글은 그 Q로
- 크리에이터 인터뷰(파란 배경 집 소개 기획, map `note`에 표시): `sec`는 `크리에이터 인터뷰 > <인터뷰 제목>`, Q 제목을 붙이지 않음, `doc`은 `cases`, 이름 · 닉네임은 빼고 "크리에이터"로
- 218쪽 참여자 목록, 사진뿐인 쪽은 넣지 않음

## doc

- `book`: 본문 · 체크리스트 · 공통 의견 요약
- `cases`: 사례 인용 · 설문 금액 표(평형별 공사비 등). 검색이 비용 · 법 · 안전 질문에서 빼는 종류(`platform`)로 들어감

## 사례 인용

- 출처 줄: 시공 방식 + 집 정보 그대로(예: `출처: <가구 수>·<평형>·<준공 연도> 아파트·턴키`). **닉네임 · 실명 · 계정은 적지 않음**. 원문에 없는 시공 방식을 추정해 넣지 않음

## trades

- 도배 · 목공 내용: `["도배"]` · `["목공"]` · 둘 다
- 공정과 상관없는 일반 내용, 여러 공정을 나열한 목록: `[]` (검색이 "공통"으로 봄)
- 그 밖의 공정만 다룸: 공정 이름 그대로 `["욕실"]` · `["설비"]` · `["바닥"]` (검색이 "범위 밖"으로 봄). 비우지 않음

## topics

- 아래 값 중 하나. 맞는 게 없으면 `general`. 검색은 이 값을 쓰지 않음
- `budget` · `table` · `case_note` · `case_summary` · `quote_review` · `checklist` · `general`

## hints

- 청크마다 고객이 물을 법한 질문 1~2개, 고객 말투로. 책 낱말과 다른 말을 섞음
  - 예: 예비비 청크 → "공사할 때 여유 돈은 얼마나 남겨 둬요?"
- 청크에 없는 내용을 묻지 않음

## 검수

- 1차 · 2차를 따로 읽고 `diff.py`로 비교. 어긋난 곳만 300dpi로 다시 봄
- 숫자 · 표 · 각주는 어긋나지 않아도 300dpi로 한 번 더 봄
- 합계 · 비율은 산술로 확인
- 무작위 10% 쪽은 사람이 원문과 나란히 놓고 확인
- 출처 줄의 집 정보 · 덧붙은 정보(가구 수 · 평형 · 준공 연도, 절감 비율 등)는 남김. 닉네임 · 실명 · 계정만 뺌. 시공 방식이 없으면 남은 정보만
- 금액 · 비용 배수 · 견적이 들어간 표와 문장은 출처와 상관없이 모두 `cases`(설문 · 계약 집계 · 사례 모두). 상담의 금액은 계산 엔진만 만들기 때문. 예: 평형별 공사비, 공사 범위별 예상 비용, 몰딩 방식별 견적 비교, 바닥재 비용 배수

## 형식 통일 (1묶음 비교에서 정함)

- `sec` 깊이
  - Q 표지 도입 글: `Q 제목`
  - 핵심 정리 큰 제목 아래 도입 문단: `Q 제목 > 큰 제목`
  - ■ 소제목: `Q 제목 > 소제목` (■ 기호 · 큰 제목은 넣지 않음)
  - 100인의 시공 노트 사례: `Q 제목 > 노트 제목 > 사례 제목`, 공통 의견: `Q 제목 > 노트 제목 > 공통 의견`
  - 인터뷰: `크리에이터 인터뷰 > 인터뷰 제목` · `시공 선배 이야기 > 제목`. 질문 문장은 본문 첫 줄
- 소제목 · 사례 제목 · "공통 의견"은 문맥 머리에만 쓰고 본문 첫 줄에 다시 쓰지 않음 (인터뷰 질문은 예외로 본문에 씀)
- 체크리스트의 쓰는 칸 이름(양식의 칸 제목) · 빈칸 제목은 뺌. 체크 항목과 안내문만
- 본문 사이 인용 상자(닉네임 붙은 회색 글상자)는 따로 `cases` 조각, `sec`는 그 ■ 절과 같게
- 뜻 있는 사진 설명(집 · 공사 설명)은 `cases` 조각으로 넣고 닉네임만 뺌. 꾸밈 소개뿐이면 뺌
- 금액 칸이 모두 0인 양식은 0 값을 넣지 않고 칸 이름 · 비고만
- trades: 사례 · 본문이 한 공정을 직접 다루면 그 공정, 여러 공정을 함께 다루면 `[]`. 공정 이름은 이 중에서: 도배 · 목공 · 바닥 · 욕실 · 주방 · 타일 · 전기 · 조명 · 설비 · 새시 · 중문 · 필름 · 가구 · 확장 · 철거
