## 1. 큰 그림: 요청이 어디로 가나

```
사용자 브라우저
   │
Cloudflare (DNS · HTTPS · 방화벽)
   │
Caddy (EC2, Docker Compose)
   ├─ /api/*  → FastAPI (backend/app)  ──→ PostgreSQL 17 + pgvector (운영: RDS)
   │                                   ──→ Redis (큐 · 요청 제한 · 짧은 캐시)
   │                                   ──→ 파일 저장소 (운영: S3, 로컬: 디스크)
   │                                   ──→ LLM API (agent/llm.py 한 곳)
   └─ 나머지  → Next.js (frontend)  ──(서버 컴포넌트가 읽기)──→ FastAPI
                                    
Redis 큐 → arq worker (견적 설명 · 단가 수집 · 알림 같은 느린 일) → PostgreSQL
```

- **화면은 계산 · DB · LLM을 하지 않아요.** 금액 · 수량 · 날짜는 모두 백엔드 `calc`가 만들어요.
- **읽기**: 서버 컴포넌트(`page.tsx`) → `lib/api/<영역>.ts` → `lib/backend/server.ts`(쿠키를 넘김) → API.
- **쓰기**: 브라우저 → 같은 주소 `/api/*`(`lib/backend/client.ts`) → API. Server Action은 쓰지 않아요.

`ROUTERS`에 지금 등록된 것: account · auth · files · notify · project · quote · schedule · vendor · visit (9개, 이름 순).

### 2-2. 층 규칙 (꼭 외울 것)

```
조립   main.py | worker.py | mcp_server.py
흐름   chat → schedule → visit → quote
대상   account | project | vendor
기반   files | refprice | jobs | knowledge | notify  → auth
도구   agent → calc
공통   shared → db | queue → config
```

- 위는 아래를 부를 수 있고, 반대는 안 돼요. `|`끼리는 서로 import하지 않아요.
- 다른 기능은 **그 기능 service의 공개 함수로만** 불러요. router끼리 import 금지.
- `calc`는 DB · HTTP · 시계를 몰라요. 오늘 날짜도 인자로 받아요.
- `agent`는 기능 service를 import하지 않아요. 데이터는 `chat/tools.py` 도구로 받아요.

### 2-3. 한 기능 안의 파일 역할

| 파일 | 역할 | 예 |
| --- | --- | --- |
| `router.py` | HTTP 입구, 권한 확인(`deps`) | `POST /projects` |
| `service.py` | 업무 흐름 · 상태 바꾸기 · commit | `project.service.create` |
| `repository.py` | DB 읽기 · 쓰기 | `select(...)` |
| `schemas.py` | 요청 · 응답 모양(Pydantic) | `ProjectOut` |
| `models.py` | DB 표(SQLAlchemy) | `Project` |

호출 순서: `CatchAll`(처리 못 한 오류 → 같은 모양) → `BodyLimit` → Origin 확인 → `router` → `deps` → `service` → `repository` → PostgreSQL. 오류는 모두 `{"error": {code, message, fields?}}`.

### 2-4. 상태를 바꾸는 법 (팀 규칙의 핵심)

1. 허용 전이인지 확인해요 (예: visits `requested → quoted`).
2. 조건부 UPDATE를 해요. 바뀐 행이 1개가 아니면 409를 돌려줘요 (동시 요청 방어).
3. 같은 트랜잭션에 이력 행(`visit_events` · `deal_events`)과 알림(`notify.service.add`, `dedup_key`로 한 번만)을 써요.

## 5. 에이전트 `agent` — 뼈대가 서 있는 단계

```
대화 한 턴: gate(입구 관문) ─┬─ fixed(정해진 답: 범위 밖 등)
                            ├─ orchestrator(복합 요청)
                            ├─ trade(공종 전문가: 도배 · 목공)
                            ├─ quote_explanation(견적 설명)
                            └─ schedule(공정표, 일정 MCP)
                         → output_check(숫자 · 모양 검사) → 답
```

| 파일 | 상태 |
| --- | --- |
| `graph.py` (70줄) | 노드 연결 완성 (`gate → 담당 → output_check`) |
| `gate.py` (72줄) · `intent.py` · `intent_lr_v1.json.gz` | 의도 분류(직접 학습한 모델) + 신뢰도 낮으면 Jev 한 번 → 그래도 낮으면 되묻기. 범위 밖은 "지금은 아파트 도배와 목공만 도와드려요." |
| `llm.py` (96줄) | `structured(role, schema, messages)` 한 함수. `LLM_LIVE=false`면 스텁(유료 0회). 실호출은 **langchain_openai `ChatOpenAI`**, 모델 설정 `openai_agent_model` |
| `schemas.py` (71줄) | `TurnContext` · `Intent` · `Card` · `Section` · `AgentAnswer` · `ChatState` |
| `trade_agent.py` (9줄) · `orchestrator.py` (8줄) · `quote_explanation_agent.py` · `schedule_agent.py` | **아직 껍데기** |
| `trades/base.py` · `dobae.py` · `mokgong.py` · `extract.py` | 공정별 설정 자리 |

**답 모양 약속** (`docs/agent-contract.md`)
- 전문가 하나 = `Section` 하나 (제목 → 결론 1~3문장 → 주의 → 팁).
- 금액 · 수량 · 날짜는 문장에 쓰지 않고 `Card(kind="standard_quote")`처럼 카드로 붙여요. 화면이 계산 결과로 채워요.
- LLM이 실패하면 `AgentAnswer(failed=True)`. 규칙으로 만든 가짜 설명은 금지.
- 에이전트는 DB에 쓰지 않아요. `user_id` · `project_id`는 서버가 정해요.
- 상한: 에이전트별 도구 4회, 턴당 하위 호출 3회.

**우리 MVP 대화와 다른 점**: 우리는 Claude가 `set_style` · `pick_material` 같은 **화면 바꾸기 도구**를 부르고 브라우저가 실행해요. 팀 방식에서는 에이전트가 화면을 직접 바꾸지 않고 **카드**를 돌려주고, 저장은 사람이 누른 요청으로만 해요. 그래서 우리 도구는 "카드 + 버튼"으로 바꿔 옮겨야 해요.

## 10. 얹는 구조 제안 — 기존 파일은 그대로, 새 파일만

원칙
- 팀 파일은 **고치지 않아요.** 새 폴더 · 새 파일만 더해요.
- 피할 수 없는 공용 한 줄은 예외로 따로 알려요: `main.py`의 `ROUTERS`에 `mvp_router` 한 줄, (표를 만들면) `migrations/env.py` models import 한 줄, `pnpm gen:api`로 다시 만드는 `schema.d.ts`.
- 팀 규칙(층 · 계산은 calc만 · 해요체 · 토큰 색)은 새 코드에도 똑같이 지켜요.

```
backend/app/
  calc/                         (기존 파일은 그대로)
    plan_qty.py        [새]     도면 공간 → 벽 · 천장 · 몰딩 · 걸레받이 · 문 수량 (CALC9.fromPlan 이식)
    mvp_dobae.py       [새]     도면 수량 + 팀 DobaePrices → 도배 금액 (팀 dobae.quote와 같은 줄 모양)
    mvp_mokgong.py     [새]     자재 선택 + 팀 MokgongPrices → 목공 금액 (CALC10.mokgong 이식)
    market_band.py     [새]     시장 기준 범위 (MARKET 이식, band_plan 포함)
  refprice/
    mvp_materials.py   [새]     목공 자재 가격표 · 출처 · 근거 종류(공공 · 시장 · 가정), 버전
    mvp_market.py      [새]     시장 범위 계수(코드 상수, 출처 · 버전)
  mvp/                 [새 기능 패키지, 흐름 층]
    router.py                   GET /mvp/plans, POST /mvp/projects/{id}/quote-preview …
    service.py                  project · quote의 공개 함수만 불러 씀 → calc 새 파일
    schemas.py
  (표가 필요할 때만) migrations/versions/0021_mvp_*.py   도면 선택 · 자재 선택 저장
backend/tests/
  test_calc_plan_qty.py · test_calc_mvp_mokgong.py · test_calc_market_band.py  [새]
frontend/
  app/mvp/             [새 라우트 묶음, 기존 라우트는 그대로]
    page.tsx                    스타일 고르기 → 공사 순서 (첫 화면 사진 한 줄 포함)
    plan/page.tsx               도면 고르기
    materials/page.tsx          목공 자재 고르기 · 도배 등급
  components/mvp/      [새 영역]  StyleStrip · PlanPicker · QtyCard · MokPanel · MarketBand
  lib/api/mvp.ts       [새]     서버 쪽 읽기 입구
evaluation/mvp/        [새]     우리 대화 eval (보류가 풀리면)
docs/mvp/              [새]     구조 · 기능 표 · 화면 표
```

## 12. 공부할 때 읽는 순서

1. `AGENTS.md` (dev판) — 규칙 전체
2. `docs/v2/structure.md` → `features.md` → `erd.md` — 무엇이 어디 있는지
3. `docs/agent-contract.md` → `docs/reference-data.md` — 에이전트 · 기준 자료 약속
4. 코드 한 줄기 따라가기
   - `backend/app/main.py` → `project/router.py` → `service.py` → `repository.py`
   - `calc/dobae.py` (`DobaeInput` → `quote`) → `quote/service.py`의 `ensure_standard`
   - `agent/graph.py` → `gate.py` → `llm.py`
   - `frontend/app/projects/[id]/standard/page.tsx` → `lib/api/quote.ts` → `lib/backend/server.ts`

**용어 짧게**
- 표준견적서(`standard_quote`): 공공 단가로 믿집이 계산한 참고 금액
- 가견적(`estimate`): 업체가 확인한 단가 × 표준 수량
- 실측 견적서(`vendor_quote`): 업체가 낸 파일 + 요약 칸
- 품(`man_day`): 기능공 1명 1일 작업량, 0.5 단위 올림
- 브리프(`brief`): 상담으로 모은 공정별 조건
