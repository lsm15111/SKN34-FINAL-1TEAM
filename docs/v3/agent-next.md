## 2. 구조: 지금 뼈대를 지키고 세 곳을 고쳐요

### 2.1 왜 지키나

- 지침은 모두 '단순한 것부터'예요. 라우팅은 입력 종류가 뚜렷하고 분류가 정확할 때 쓰는 고정 흐름이에요(A1).
- 여러 에이전트의 이득은 나눠서 동시에 하는 일에 한정돼요.
  - 토큰은 대화의 약 15배가 들어요.
  - 순서가 있는 과제는 오히려 −39~70%였어요(A2).
  - 하나로 이어지는 일을 오케스트레이터에 맡기면 계획 · 넘김 · 합치기 비용만 더 내요(Anthropic 비용 지침).
- 믿집 질문은 대부분 한 공종 · 한 의도예요. 여러 공종 질문도 무료 모드는 LLM 없는 고정 흐름이라, 토큰 문제는 LLM 모드에만 생겨요.
- 지금 지켜 온 '깊이 1 · 담당끼리 서로 안 부름 · 담당 답을 다시 쓰지 않음'은 근거와 맞아요.
  - 중앙형이 오류 번짐이 작아요(A3).
  - 감독자가 답을 옮겨 말하면 손실이 생겨요(A5).

### 2.2 고칠 곳 ① 관문: 기준 둘 + 확인 단추

- 지금은 분류기 신뢰도 0.7 하나예요. 이 값은 Rasa 예시값과 같지만 측정으로 정한 값은 아니에요(A7).
- 바꿀 모양
  - **높음**: 담당에게 바로 보내요.
  - **중간이거나 1 · 2위 차이가 작음**
    - 무료 모드: 후보 단추 2~3개로 확인해요.
    - LLM 모드: 짧은 판정 1회를 써요. 불확실한 것만 LLM에 올리면 정확도 차는 약 2%, 지연은 약 절반이에요(A6).
  - **낮음**: 범위 밖 안내 + 믿집이 할 수 있는 일을 보여요.
  - 확인 단추는 대화당 1회까지만 써요.
  - 기준은 dev의 '처리율-오답률' 곡선에서 골라요.
- 범위 밖은 분류 정확도와 따로 움직여요(범위 안 96.9% vs 범위 밖 찾기 40.3%, E4).
  - '같은 분야 안 범위 밖'(바닥 · 욕실 · 전기 금액, 가전 · 이사)은 예시를 따로 모아 평가해요.
  - 오늘 범위 밖 규칙을 고쳤어요. 기술 배우기 · 가전 청소는 늘 범위 밖이고, 집값 · 소품은 공종 낱말이 없을 때만 범위 밖이에요(`beginner_eval.md` 5장).
- 담당(4)과 질문 꼴(11)은 곱해 펼치지 말고 두 칸으로 따로 분류해요. 라벨이 많을수록 범위 밖 판정이 나빠져요(A6).

### 2.3 고칠 곳 ② 오케스트레이터: 찾기 몫을 공종별로

- 나누기는 코드로 해요(공종 낱말 위치 + 이음말). 빠진 말은 원 질문에서 채워요('둘 다 얼마나 걸려요?').
- 찾기는 공종마다 위 k개씩 해요. 전체 위 k개로 찾으면 한 공종이 결과를 독식해요.
- 붙이기는 담당 답을 다시 쓰지 않고 공정 순서로 이어요.
  - 같은 글 묶음은 한 번만 넣어요(오늘 구현).
  - 못 찾은 공종은 한 줄로 모아요(오늘 구현).
- 순서 · 기간처럼 공종끼리 얽힌 질문은 나누지 않아요. 공정표 담당과 계산 엔진 하나로 보내요.
- 목표: E4 조각 덮기 0.26을 올려요. B5 때 0.66에서 떨어진 원인부터 찾아야 해요(8장 P1 앞).

### 2.4 고칠 곳 ③ 모를 때 막다른 길 없애기

- 기준에 못 미친 가까운 카드 2~3개를 "이걸 물으셨나요?" 단추로 보여 줘요. 하단 기준 아래면 후보도 안 보여요(A 제안 6, B 제안 4).
- 확인할 곳은 질문 꼴에 맞춰요. 예: 제품 고르기 → 실측 때 업체, 단지 규칙 → 관리사무소.
- 못 답한 질문은 덮기 운영 루프(5.3)의 재료로 모아요.

### 2.5 하지 않을 것

- 담당 늘리기, 담당끼리 직접 넘기기(스웜)(A2 · A3 · A4)
- 관문을 LLM 분류로 통째 바꾸기(A6)
- 오케스트레이터가 담당 답을 요약 · 의역하기(A5)
- 처리율(자동화율)만 성공으로 보기(A10)
- 근거 없을 때 일반론으로 그럴듯하게 채우기(A11)

## 3. 성능: 뜻으로 찾기(실행은 무료)

## 4. 비용 · 지연

### 4.1 원칙

1. **무료 모드가 기본이에요.** 카드 · 조각 요약 · 정해 둔 글 · 계산 엔진으로 답하고 LLM은 0회예요.
2. **LLM은 애매할 때 두 곳만** 써요(A 제안 7).
   - (가) 카드 점수가 애매할 때 질문을 표준 문장으로 다시 써서 다시 찾기(짧은 출력 1회)
   - (나) 여러 공종 조각을 짧게 엮기
3. **미리 만들기**(오프라인)
   - 카드 · 한 줄 결론 · 초보 말투 열쇠를 미리 만들고 검사 · 검수해 둬요. 실행 중 비용은 0이고, 숫자 · 말투를 통제할 수 있어요(C 제안 3).
   - 하위 에이전트로 만들면 0원이에요. API Batch로 만들면 50% 할인이에요(C3).
4. **작은 모델 먼저**: 출력 검사에서 떨어질 때만 큰 모델로 다시 답해요(C7).
5. **요청 모양을 고정**해 캐시가 맞게 해요. 순서는 도구 → 지침 → 이전 대화 → 이번 근거예요. 대화 중 effort · 도구를 바꾸지 않아요(C2).

- 캐시는 OpenAI가 자동(최소 1,024토큰, 기본 30분)이고, Claude는 표시한 곳부터(최소 512토큰, 기본 5분)예요. 뜸하게 오는 믿집 대화는 OpenAI 쪽 캐시가 덜 식어요(C17).
- 긴 입력 할증: Haiku 5.5는 프롬프트 10만 토큰을 넘으면 $0.50 / $2.50, OpenAI는 입력 27만 2천 토큰을 넘으면 입력 2배 · 출력 1.5배예요. 믿집 요청(수천 토큰)과는 상관없어요.
- 임베딩: text-embedding-3-small $0.02예요. 질의 임베딩은 1만 대화 기준 월 약 $0.05예요(C18).

### 4.3 대화 비용(조사 담당 계산 · 가정은 research C)

대화 1번 = 4턴, 캐시 켬, 답 350토큰, 추론 · 생각 토큰 0으로 가정했어요.

| 경우 | luna · Haiku 5.5 | terra | Sonnet 5.5 | Opus 5.5 |
| --- | --- | --- | --- | --- |
| 모든 턴을 LLM이 답함, 1,000대화 | $2.1 | $21 | $41 | $106 |
| 무료 모드가 턴의 70%를 맡음, 1,000대화 | 약 $1 | $6~10 | $12~21 | $32~49 |
| 10,000대화(모든 턴 LLM) | $21 | $206 | $411 | $1,063 |

- **계단 방식**(작은 모델 먼저, 검사 실패 턴만 큰 모델, 실패율 20%): luna → terra는 1,000대화 $9.1(terra만보다 −56%), Haiku → Sonnet은 $16(Sonnet만보다 −61%)이에요. 실패율이 53~56%를 넘으면 큰 모델만 쓰는 쪽이 싸요.
- **추론 · 생각 토큰**: 턴마다 200토큰을 더하면 1,000대화가 terra $25 · Sonnet $49 · luna · Haiku $2.5예요.
- **카드 미리 만들기**(1,500장, 생성 + 판정, Batch): terra 약 $12, Sonnet만 약 $23, Opus 생성 + Sonnet 판정 약 $37이에요. 하위 에이전트로 만들면 0원이에요.
- **한국어 토큰**: 할증은 5.5 세대에서 작을 가능성이 커요(추정, C8). gpt-6.x의 한국어 배율은 확인하지 못했어요. 같은 한국어 샘플을 양쪽에서 재요(Claude는 무료 토큰 세기, OpenAI는 응답 usage).

### 4.4 지연 목표

- 첫 글자 p50: 카드 경로 1초 이하, LLM 경로 3초 이하. 끝까지는 10초 이하예요(C10).
  - GOV.UK Chat은 평균 10.7초가 불만이었어요(D10).
- 카드 경로는 DB 조회만 해요. LLM 경로는 SSE로 흘리고, 1초가 넘으면 '답을 준비하고 있어요'를 보여요.
- 생각(thinking) 시간이 지연의 대부분이에요. 다시 쓰기 같은 짧은 일은 생각을 끄거나 low로 둬요(C9).

### 4.5 상한 · 관측

- 사용자별 하루 상한을 토큰이 아니라 **금액**으로 둬요.
  - 응답의 usage(입력 · 캐시 읽기 · 캐시 쓰기 · 출력)를 단가표 버전과 함께 받아요.
  - Redis로 바로 확인하고, 호출 1건을 1행으로 남겨요(C 제안 4).
- 조직 월 지출 상한에 닿으면 429예요. 그때는 무료 모드로 내려가게 해요(C13).
- 사용량 API는 4~24시간 늦어요. 그래서 실시간 차단에는 앱 안 계산을 써요.

### 4.6 공급자

- 지금 v3 코드(`backend/app/agent/llm.py`)는 OpenAI예요. ADR [agent-06](adr/agent-06-llm-provider.md)은 'OpenAI 유지'를 권하고 사용자 확인을 기다려요.
- 이 설계의 구조(무료 기본 · 애매할 때만 · 작은 모델 먼저 · 미리 만들기)는 공급자와 상관없어요.
- 단가로 보면 OpenAI가 같거나 싸요(작은 모델은 같고, 큰 모델은 절반).
- 지연(영어 위주 벤치마크, 첫 글자까지)
  - 지금 설정(luna 추론 없음, terra low)은 1.5초 · 3.1초예요. Claude Sonnet 5.5 low 2.3초 · Haiku 5.5 low 5.7초와 같거나 빨라요(C9 · C20).
  - 같은 벤치마크에서 Claude 쪽은 과제마다 토큰을 훨씬 많이 썼어요.
  - 품질 점수는 보지 않았어요.
- 그래서 공급자는 단가표가 아니라 **같은 한국어 평가 세트를 양쪽에서 돌려** 정해요.
  - usage(입력 · 캐시 · 출력 · 추론 토큰)와 품질을 같이 재요.
  - 유료라 허락을 받은 뒤 표본만 돌려요.
- 임베딩
  - Anthropic은 임베딩 모델이 없어요. LLM을 Claude로 바꿔도 이미 넣은 1536차원 벡터(text-embedding-3-small)는 그대로 쓸 수 있어요(C18).
  - 임베딩을 로컬(KURE-v1)로 하면 어느 쪽이든 API 의존이 하나 줄어요.

### 5.2 긴 꼬리는 카드로 다 덮지 않아요

- 업계 사례에서 의도 · 카드로 덮는 비율은 약 40% 근처에서 멈췄어요(E2).
- 꼬리 쪽 질문은 다음으로 맡겨요.
  - 조각 검색(뜻 검색)
  - '근거가 충분한가' 판정(E6)
  - 정직한 모름 + 가까운 카드 제안(2.4)

### 5.3 덮기 운영 루프(서비스를 연 뒤 매주)

1. **모으기**: '확인 못 함', 되묻기 뒤 떠난 대화, 같은 대화에서 다시 물은 질문, 업체 연결로 간 대화를 모아요. 전화번호 · 동호수는 가려요.
2. **묶기**: 문장 벡터로 묶어요(코사인 0.7~0.9에서 시작). 상위 묶음은 사람이 합쳐요(E7).
3. **나누기**: 카드로 쓸 것 / 화면 · 기능 문제 / 범위 밖
4. **초안**: 하위 에이전트가 카드 초안을 써요. 금액 · 기간 숫자는 쓰지 않아요.
5. **검수**: 사람이 100% 봐요. `cards_check.py`로 겹침 · 숫자 · 말투를 검사해요.
6. **배포**: 회귀 세트(질문 은행)를 통과하면 내보내요.
7. **따라가기**: 묶음별 '확인 못 함' 비율을 따라가요.

- 회사 사례에서는 해결률이 한 달 1%p 안팎씩 올랐어요(E8, 회사 발표). DoorDash는 상위 묶음의 상담원 연결이 78% → 43%로 줄었어요(E7).

## 6. 다양한 질문을 짧게 설명하기

### 6.1 원칙(D)

1. **첫 문장이 답이에요.** 사용자는 '도울 수 없어요'에서 읽기를 멈추고, 둘째 문단의 해결책은 놓쳤어요(D1).
   - 예/아니요 질문은 '네 · 아니요 · 경우에 따라 달라요'로 시작해요.
   - 못 하는 일은 첫 문장에 말하고 차선책을 같이 줘요.
2. **보이는 부분은 2~3문장**이에요. 나머지는 그 자리에서 펼쳐요. 펼침은 2층까지만 둬요(D2 · D4).
3. **길이는 코드로 지켜요.** 모델은 최대 길이 지시를 44~49% 어겨요. 판정자는 사람이든 LLM이든 긴 답을 더 좋게 매겨요(D13 · D14).
4. **쉬운 말**로 써요. 한 문장에는 한 가지만 담고, 용어는 처음 나올 때 풀어요. 원문 '-다'는 옮기지 않아요(D5 · D6 · D7).
5. **출처는 가까이, 적게** 달아요. 출처를 누르는 사람은 1%뿐이고, 출처가 붙기만 해도 과신이 생겨요. 보이는 문장을 실제로 받치는 근거 1~2개만 문서 이름으로 달아요(D8 · D9).
6. **모를 때는 1인칭**으로 말하고 확인할 곳을 줘요(D11).
7. **되묻기는 한 번, 단추로** 해요. 질 낮은 되묻기는 해로워요(D12).

### 6.2 꼴별 답 틀

| 꼴 | 첫 문장 | 보이는 문장 | 글자 상한(조사 시작값) | 시제품 예산(문장 · 글자) |
| --- | --- | --- | --- | --- |
| 예/아니요 | '네 · 아니요 · 경우에 따라' + 이유 한 마디 | 1~2 | 80 | 2 · 130 |
| 뜻 | 'X는 ~예요' | 2 | 90 | 2 · 120 |
| 방법 | 먼저 할 것 · 단계 수 | 1 + 단계 3 | 150 | 3 · 170 |
| 순서 | 순서 문장(공정 순서 규칙) | 2 | 130 | 2 · 130 |
| 비교 | 조건별 결론('~가 중요하면 A') | 2 | 120 | 2 · 140 |
| 원인 | 가장 흔한 원인 1개 + 지금 볼 곳 | 2 | 100 | 2 · 120 |
| 비용 | 계산 엔진 금액(부가세 포함) + 기준, 없으면 표준견적서 단추 | 2 | 90 | 2 · 130 |
| 기간 | 예상 공정표 값 + 늘어나는 조건 | 2 | 80 | 2 · 130 |
| 하자 · 분쟁 | 판정하지 않음 + 지금 할 일(사진 · 날짜 · 업체) | 2 | 130 | 2 · 150 |
| 추천 | 못 하는 것 + 대신 하는 것(업체 비교 화면) | 2 | 80 | 2 · 110 |
| 모름 | '제가 가진 자료로는 확인하지 못했어요' + 확인할 곳 | 2 | 70 | 모름 글 그대로 |
| 되묻기 | 질문 1개 + 단추 2~4개 + '잘 모르겠어요' | 1 | 40 + 단추 | (기존 되묻기) |

- 시제품 예산은 지금 카드 문장 길이(평균 약 55자) 때문에 조사 시작값보다 조금 넉넉해요. 카드 문장을 40~60자로 다듬고 한 줄 결론(6.5)이 들어오면 조사 시작값으로 줄여요.
- 답 길이와 만족도를 직접 잰 큰 규모 연구는 없었어요(D15). 상한은 믿집 안에서 길이별로 나눠 비교(A/B)해 맞춰요.

### 6.3 화면 모양(위에서 아래)

1. **짧은 답**: 1~3문장. 맨 앞 문장이 질문에 가장 맞는 문장이에요. 다음 단계에서는 한 줄 결론을 굵게 둬요.
2. **출처 한 줄**: 보이는 답의 근거 문서 이름 2개까지
3. **'자세히 보기 · n문장 더'**: 그 자리에서 펼치고 접어요(`aria-expanded`). 안에는 전체 답 · 주의 · 팁 · 출처가 있어요.
4. **믿집 계산 상자**: 금액 · 기간은 계산 엔진 값 그대로예요.
5. **다음 할 일 단추**: 2~3개, 결과를 말하는 동사형이에요.

- 못 찾은 공종 한 줄('필름 쪽 자세한 내용은 확인하지 못했어요')은 짧은 답에 늘 보여요. 숨기면 일부만 답한 것을 모르고 넘어가요.

### 6.4 무료 모드 시제품(이 브랜치에 구현)

- **코드**
  - `backend/app/agent/v3/brief.py`: `form_of`(꼴), `make`(고르기)
  - `AgentAnswer.brief`
  - `turn.run_turn`: 출력 검사 뒤에 붙여요.
  - `/ai/turns` 응답의 `answer.brief`
  - 화면 `components/ai/AiAnswer.tsx`(접기 · 펼치기)
- **고르는 법**: 새 글은 만들지 않아요. 출력 검사를 통과한 문장에서만 골라요.
  1. 그 꼴의 정해 둔 글을 맨 앞에 둬요(추천 거절 · 하자 판정 안 함 · 표준견적서 안내 · 순서 문장).
  2. 나머지 문장은 점수 순으로 골라요. 점수 = 질문 낱말 덮기(글자 두 개 묶음) + 앞 문장 덤 + 꼴에 맞는 끝말 덤.
  3. 꼴 예산 안에서 골라, 가장 맞는 문장을 맨 앞에 두고 나머지는 원래 순서대로 둬요.
  4. 여러 공종 답은 묶음마다 하나씩 골라요. 못 찾은 공종 한 줄은 늘 넣어요.

  - 같은 길이라면 앞에서 자르기보다 고르기가 첫 문장에서 질문에 더 잘 닿고, 핵심을 덜 놓쳐요.
  - '전체적으로 더 낫다'는 아직 확실하지 않아요.
  - 기본값(접어서 보이기)은 8장에서 고를 일로 남겨요.
- **한계**
  - 카드 문장을 고르기만 하므로 예/아니요 질문에 '네 · 아니요'로 시작할 수 없어요(결론 말투 13/48).
  - 원 카드가 질문과 어긋나면 짧은 답도 어긋나요. 판정에서 23/102쌍이 '전체 답이 어긋남'이었어요. 짧게 만드는 일과 맞는 카드를 찾는 일은 따로예요(3장).

### 6.5 다음 단계: 카드 '한 줄 결론'

- 카드에 칸 하나를 더해요.

  ```json
  "lead": {"verdict": "yes | no | depends | info", "text": "40자 안쪽 해요체 한 문장", "cites": ["K…"]}
  ```

- **보이는 법**: 예/아니요 꼴이면 `verdict`에 맞춰 '네, · 아니요, · 경우에 따라 달라요.'로 시작하고 `text`를 굵게 보여요. 다른 꼴이면 `text`만 보여요.
- **만드는 법**
  - 하위 에이전트가 카드 416장의 초안을 써요(0원).
  - `cards_check.py`에 규칙을 더해요: 근거 조각 글자 겹침 ≥ 0.18, 금액 · 기간 숫자 금지, 해요체, 40자.
  - 사람이 표본을 검수해요. 판정은 키(질문) 문장 여러 개에 같은 결론이 맞는지로 봐요.
- **어려운 점**: 한 카드의 열쇠 질문들이 서로 다른 결론을 요구할 수 있어요(예: '덧방해도 돼요?'와 '꼭 뜯어야 해요?'). 이런 카드는 `verdict: "depends"`로 두거나, 열쇠별 결론 칸을 둬요.

### 6.6 LLM 모드(공급자 · 비용을 정한 뒤)

- LLM이 정하는 것은 다섯 가지 구조뿐이에요: 꼴 · 한 줄 답 · 핵심 문장 번호(≤ 2) · 자세히 번호(≤ 3) · 되묻기 선택지.
- 문장은 코드가 검사된 카드 · 조각 문장으로 붙여요. 글자 수를 넘으면 코드가 '자세히'로 내려요.
- 길이를 지시문에 맡기지 않아요(D13). 지시문도 짧게 둬요. 입력이 길면 추론이 떨어져요(D13).

### 6.7 쉬운 말 규칙(카드 · 요약 · 정해 둔 글에 적용)

1. 첫 문장은 답이에요(네 · 아니요 · 뜻 · 숫자 · 첫 단계 중 하나). 배경은 둘째 문장부터 써요.
2. 한 문장에 한 가지만 써요. 40자를 목표로, 60자를 넘지 않게 해요(추정값). '-고 · -며 · -지만'이 두 번을 넘으면 나눠요.
3. 용어는 처음 나올 때 괄호로 풀고, 용어 사전 하나로 통일해요.
   - 오늘 고친 예: 일손(품), 틈 메우는 반죽(핸디코트), 사포질(샌딩), 바탕 처리(시라)
4. 원문 '-다'는 옮기지 않아요. 원문은 출처로만 보여요.
5. 의무 · 권장 · 선택을 말로 나눠요.
   - 의무 '-해야 해요'는 법 · 규약 · 계약 근거가 있을 때만 써요.
   - 권장은 '-하는 게 좋아요', 선택은 '-할 수 있어요'로 써요.
6. 빈말(인사 · 칭찬 · 질문 되풀이)을 빼요. 명사 쌓기는 동사로 풀어요.

- 1 · 2 · 3은 코드 검사로 잴 수 있어요: 첫 문장 꼴, 문장 길이, 용어 사전에 있는데 풀이가 없는 말.

### 6.8 판정 방법(짧은 답 rubric)

- 줄마다 매기는 것
  - **better**: 질문에 더 바로 답하고 전체 답의 핵심을 더 잘 담은 쪽(A · B · same)
  - **keep**: 짧은 답이 핵심을 담았나(yes · partial · no)
  - **direct**: 첫 문장이 질문에 바로 닿나
- 지키는 것: 길이가 같은 예산 안에 있으니 길다고 좋게 보지 않아요. A · B 순서를 섞고, 순서를 바꿔 다시 읽어요. 전체 답이 어긋나면 질문 기준으로 매기고 '전체 답이 어긋남'이라고 적어요.
- 판정자 보정은 7장 순서를 따라요.

## 7. 평가 체계

| 세트 | 쓰는 곳 | 크기 |
| --- | --- | --- |
| 고정 회귀 | 질문 은행 493 + 꼭 지킬 문항(숫자 · 범위 밖 · 개인정보). 바꿀 때마다 | 지금 그대로 |
| dev | 자유롭게 보고 고쳐요 | 초보 152 |
| held-out | 봉인, 분기에 한 번. 열쇠 재료 금지 | 75 → **200~300**으로 |
| 회전 | 매달 새 질문 30~50개(서비스를 연 뒤 대화 기록에서) | — |

- 지표
  - 답한 비율과 '답한 것 중 맞은 비율'(자신 있는 오답)
  - 범위 밖 찾은 비율(같은 분야 안은 따로)
  - 되묻기가 알맞았던 비율
  - 숫자 위반 0
  - 짧은 답 지표: 보이는 글자 수 · 결론 먼저 · 풀이 없는 용어
- 표본 크기(E 계산, 같은 문항 짝 비교): 15%p 차이는 약 70~100문항, 10%p는 약 155~235, 5%p는 약 630~940이 필요해요. 75문항으로는 약 15~20%p보다 작은 차이를 가릴 수 없어요.
- 판정자
  - 기준 카드 · 근거를 함께 줘요. 순서를 바꿔 두 번 매기고, 엇갈리면 같음으로 쳐요(E10).
  - 사람 라벨 150~300건으로 kappa를 재요. 사람끼리 일치도(약 0.69) 근처를 목표로 해요(E11).
- LLM 모드는 같은 질문을 여러 번 돌려 'k번 모두 성공'으로 재요(A8). 유료라 허락 뒤에 표본만 돌려요.

4. **held-out 늘리기**: 초보 질문을 웹에서 더 모아(약 150개 더) held-out을 200개 넘게 만들지.
