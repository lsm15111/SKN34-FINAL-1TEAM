# 전체 도배 면적: 지금 계산이 큰가, 어떻게 받을까

- 조사일: 2026-11-19
- 대상: `backend/app/calc/dobae.py` `quote_v3` · `standard_v3`, `refprice/book.py` `DOBAE_2026H2`, `calc/space_share.py`
- 숫자는 모두 저장소 계산 엔진을 직접 불러 냈어요(`uv run python`, DB 없이). 코드는 고치지 않았어요.

## 0. 한눈에

| --- | --- |
| 지금 식이 큰가 | 커요. 다만 '방이 다 들어가서'가 아니라 **공급면적 × 2.5 계수 자체**가 커요. 지금 식은 방 개수를 아예 안 봐요 |

## 1. 지금 계산식

| 단계 | 식 | 값 (`DOBAE_2026H2`) |
| --- | --- | --- |
| 도배 면적(벽 + 천장) | 면적㎡ × `area_factor[기준]` | 공급 2.5 · 전용 3.0 |
| 발코니 확장 | × `balcony_factor` | 1.08 (v3 기본 정보 화면엔 칸이 없어 보통 꺼짐) |
| 천장 | 도배 면적 × `ceiling_share` | 0.25 |
| 벽 | 도배 면적 − 천장 | |
| 벽지 평 | (벽 + 천장) × `paper_ratio` 1.2 ÷ 3.3058 | 소요량에 자투리 20% 포함 |
| 부분 공사 | 벽 · 천장 × 고른 공간 몫 합(최대 1) | 몫 표 합계 1.05 |

- 방 개수 · 공간 구성은 전체 공사 계산에 들어가지 않아요. 같은 34평이면 방 2개 집도 4개 집도 같은 면적이에요.
- 이 문서의 '롤'은 실크 1롤 = 1.06m × 15.6m = 16.5㎡ = 벽지 약 5평이에요. 지금 식의 롤 = 벽지 평 ÷ 5(자투리 20% 포함)예요.

## 4. 경쟁 · 비슷한 서비스는 '전체 도배'를 어떻게 받나

| 서비스 | 면적 | 방 · 공간 | 천장 | 확장 | 확인 방법 |
| --- | --- | --- | --- | --- | --- |
| 집닥 견적계산기 | '평형(공급면적)' 5~70평 목록, ㎡ 같이 표시 | '공간의 구조가 어떻게 되나요?' 방 수 · 욕실 수 · 발코니(베란다) 수 버튼. **평형을 고르면 기본값이 채워짐**(34평 → 방 3 · 욕실 2 · 발코니 2, 56평 → 방 5 · 욕실 3 · 발코니 2). 평형에 안 맞는 개수는 흐리게 막음. 안내: "인테리어 예정이 아닌 공간도 함께 선택해 주세요." 다음 단계에서 현관 · 거실 · 주방 · 방1~3 · 욕실 · 발코니 **공간마다** 도배를 안 함 / 실속형(합지) / 기본형(실크) / 고급형으로 고름 | 따로 칸 없음(거실 항목에 '천장.조명'이 따로 있음) | 발코니 개수로만 받음 | 2026-11-19 직접 열어 봄. 34평 실크: 거실 66만 · 방마다 37만 → 거실 + 방 3 = 176만원. 주방 · 현관에는 도배 칸이 없음 |
| 도배르만 견적 계산기 | 전용 평형(평) | 방 갯수, '거실+주방 포함' 예/아니오 | 도배 범위: 전체 · 벽만 · 천장만 · 부분도배 · 거실만. 천장 높이 4단계 | '면적 보정(%)'(발코니 확장 등) | WebFetch 2026-11-19 |
| 숨고(요청서) | 요청서 화면은 **확인 못 함**(로그인 · 404). 블로그는 '평수 · 천장 포함 여부 · 기존 벽지 상태'를 사진과 함께 보내라고 안내 | | | | 블로그만 확인 |

| devcomma 벽지 계산기 | 방 가로 · 세로 · 높이(m) | 시공할 벽면 수 1~4면 · 전체, 문 · 창 크기 | 벽면만 / 천장 포함 | — | WebFetch(방 한 칸 단위 계산기) |

정리

- 평형만 받고 끝내는 곳은 없어요. **평형 + 방 개수**(집닥 · 도배르만)가 가장 흔하고, 집닥은 방 개수를 평형으로 미리 채워 줘요.
- '전체'를 고르게 하기보다, 공간 목록을 보여 주고 공간마다 할지 말지 고르게 해요(집닥). 도배르만은 '전체 · 벽만 · 천장만 · 부분 · 거실만' 범위 칸이에요.
- 확장은 칸을 따로 두기보다 발코니 개수(집닥)나 보정 %(도배르만)로 받아요.

## 5. 방안

공통: 대표 평형은 24평(공급 79.3 · 방 3), 34평(공급 112.4 · 방 3), 44평(공급 145.5 · 방 4). 실크, 빈집, 확장 집, 천장 포함. 기준값은 평면도 중앙값(24평 189.8 · 34평 242.4 · 44평 약 291㎡)과 실견적 롤(13.4 · 17.8 · 22.3롤).

### 방안 1. 계수만 바로잡기 (화면 그대로)

| 항목 | 내용 |
| --- | --- |
| 입력 화면 | 지금과 같음. 전체 / 부분, 면적 |
| 계산 | `area_factor` 공급 2.5 → 2.2, 전용 3.0 → 2.9, `ceiling_share` 0.25 → 0.35. 확장은 기본으로 보고(공고 평면 대부분 확장), 비확장이면 × 0.86(1.90 ÷ 2.19)으로 `balcony_factor` 방향을 뒤집음 |
| 장점 | 코드 한 곳(`book.py` 값) · 판 올리기만. 자료 두 갈래(평면도 2.19 · 실견적 2.21)와 시장 계산(`market.py` 2.24)이 같은 값을 가리켜요 |
| 단점 | 고정 배수라 작은 집은 작게, 큰 집은 크게 나오는 문제가 남아요. 사용자가 말한 '전체여도 방을 고르고 싶다'는 해결 못 해요 |

### 방안 2. 평형 + 방 개수 (전체 공사 안에 '방 개수' 칸)

| 항목 | 내용 |
| --- | --- |
| 입력 화면 | 면적 아래 '방 개수' 버튼 1 · 2 · 3 · 4 · 5. 평형으로 기본값을 채움(22평 미만 2, 22~39평 3, 40평 이상 4 — 평면도 20곳 · 집닥 34평 → 3 기준). 고객이 바꿀 수 있음 |
| 계산 | `도배 면적 = 1.55 × 공급㎡ + 20.4㎡ × 방 개수`(확장 20곳 회귀), 천장 0.35. 전용으로 넣으면 공급 = 전용 × 1.315로 바꿔서 씀 |
| 장점 | 집 크기별로 가장 잘 맞아요(아래 표). 방 개수는 고객이 확실히 아는 값이고, 집닥 · 도배르만도 받는 칸이에요 |
| 단점 | 칸이 하나 늘어요. 회귀 근거가 20곳(4방 2곳)뿐이에요. '방 개수'는 집 구조이지 '할 범위'가 아니라서 '방 하나는 안 해요'는 여전히 못 받아요 |

### 방안 3. 전체 = 모든 공간 체크, 안 하는 곳을 빼기 (공간 몫 재사용)

| 항목 | 내용 |
| --- | --- |
| 입력 화면 | '전체 / 부분' 둘을 없애고 공간 칩 목록 하나: 거실 · 주방 · 안방 · 작은방 1 · 작은방 2 · 복도 · 현관 · 드레스룸. 처음엔 모두 켜짐(= 전체). 끄면 빠짐 |
| 계산 | 집 전체 면적(방안 1 계수) × (1 − 끈 공간 몫). 몫 표 합계를 1로 맞춤(지금 1.05) |
| 장점 | 지금 `space_share`와 `share` 입력을 그대로 써요. '방 하나만 빼고 다' 같은 말을 바로 받아요. 블로그 사례(C05 '드레스룸 제외')와 맞아요 |
| 단점 | 집 전체 면적은 여전히 고정 배수라 큰 집이 커요. 방이 2개인 집에도 작은방 2 칩이 보여요. 몫이 3방 기준이라 2방 집에서 방을 빼면 적게 빠져요 |

### 방안 4. 방안 2 + 방안 3 합치기 (추천)

| 항목 | 내용 |
| --- | --- |
| 입력 화면 | ① 면적(지금처럼). ② '방 개수' 1~5, 평형으로 기본값(바꾸기 가능). ③ 공간 칩 목록: 방 개수만큼 '안방 · 작은방 1 · 작은방 2 …'가 생기고 모두 켜진 채 시작 = 전체. 끄면 빠짐. ④ 면(벽 · 천장) — 지금 부분 공사 칸을 전체에도 씀. 발코니 확장은 '모름 = 확장'으로 두고 실측에서 확인 |
| 계산 | 집 전체 = `1.55 × 공급㎡ + 20.4 × 방 개수`, 천장 0.35. 빼기는 방 개수별 몫 표(2방: 0.25 · 0.22, 3방: 0.18 · 0.16 · 0.15, 4방: 0.17 · 0.16 · 0.11 · 0.05, 나머지 공간은 지금 표를 방 몫 합에 맞춰 다시 나눔). 몫 표는 `space-share-2026.11` 다음 판으로 견적에 고정 |
| 장점 | 집 크기 · 구조 · 범위를 다 받아요. 집닥 흐름(평형 → 구조 기본값 → 공간마다 고르기)과 같아 고객이 낯설지 않아요. '전체 / 부분'으로 나뉜 지금 화면과 계산 경로가 하나로 합쳐져요 |
| 단점 | 손이 가장 많이 가요: `HomeV3`에 방 개수, 몫 표 판 올리기, 화면 칩 동적 생성, 표준견적서 가정 문구, migration(방 개수 칸). 회귀 근거가 20곳뿐이라 평면을 더 모으면 값을 다시 맞춰야 해요 |

## 7. 확인 못 한 것

- 업계 '평형별 롤 수 표'(예: 33평 전체 몇 롤)를 공개한 곳은 찾지 못했어요. 실견적 롤 수(3-2)로 대신했어요.
- LX지인 · 개나리 · 신한의 공식 소요량 계산기는 찾지 못했어요.
- 숨고 요청서 · 오늘의집 시공 견적 화면은 열지 못했어요(로그인 · 403).
- 실견적 평형이 공급인지 전용인지는 글에 거의 없어서 확인 못 했어요. 공급으로 보고 비교했어요.
- 44평 평면도 기준(약 291㎡)은 38평 · 47평 두 평면 사이 보간값이에요.
- 집닥 계산기는 같은 브라우저 상태가 남아 24평 기본 방 개수는 보지 못했어요(34평 · 56평만 확인).
