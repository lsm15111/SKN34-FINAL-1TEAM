## 2. 바꾼 것

- `planner.py` · `prompts/planner_v1.md`: LLM 모드 · 표준견적서 · 업체 자세히 화면에서만. 화면 항목(키 · 이름 · 짧은 뜻)을 받아 조각 · 꼴 · 항목 키를 줘요. 목록 밖 키는 버리고 조각은 3개까지. 실패하면 지금 관문 길이에요.
- `screen_tools.py`: 꼴 → 담당(코드가 골라요). 줄을 가리키면 견적 설명이 그 줄을 풀고(`Task.item`), 비교 · 판단은 비교 도구(`Task.want`), 순위는 도구 없이 작성기가 '보는 화면'으로 답해요. 같은 일은 한 번, 턴당 3번까지.
- '보는 화면' 근거(`rule:screen`): 합계 · 공급가 · 부가세 · 표준 대비 % · 벽지 바꾸면 차이 · 줄(금액 큰 순서, 단가 × 수량 = 금액, 표준에 있는지, 시장 기준값) · 표준견적서 줄 · 다른 업체 가견적. 모두 계산 엔진 값이에요.
- `composer_v7` 화면 꼴: 화면 숫자 그대로 · 판단 말 가능 · 업체를 고르라는 말 금지 · 줄 질문은 셈 풀이를 되풀이하지 않고 그 비용이 무엇인지 · 왜 따로 받는지.
- 코드 검사: 인용을 비웠어도 숫자가 모두 화면 값이면 화면 인용 문장으로 봐요. 화면 꼴의 판단 문장('~보다 높은 편이에요')은 고정 몫과 같은 숫자를 써도 되풀이로 빼지 않아요.
- 업체 가견적 비교 상자가 같은 ref라 하나로 합쳐지던 것을 업체마다 따로 둬요.

- 한 턴 3~10초. 지시문 캐시가 없는 첫 턴은 10~12초예요(분석 + 작성 두 번).
- 스텁 테스트: `tests/test_v3_agent_planner.py` 9개(항목 목록 · 정리 · 보는 화면 글 · 판단 · 순위 · 줄 · 표준 줄 · 실패 길 · 데이터 없는 화면).

## 4. 남은 것
