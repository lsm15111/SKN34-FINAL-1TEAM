# v3 무료 모드에 의미 검색으로 카드 다시 확인하기 (2026-11-19)

- 대상: `feat-v3-agent-design`(a92f1dc 위 작업 사본), 무료 모드(`LLM_LIVE=false`). 점검 스크립트는 `llm.structured` · `jev_choice` · `embed_query`를 부르면 오류가 나게 막았어요.
- 유료 호출: 점검 질문 임베딩만(text-embedding-3-small). LLM 답 쓰기 호출은 0회예요.
- 지식: 저장소 색인(`tests/v3_kb.repo_kb`, 조각 2,478) + 카드 416장. 개발 DB `mitjip_v3` 적재본과 조각 2,478개 · rid · ref가 모두 같아서, 의미 검색 순위만 DB(`knowledge.nearest`)에서 만들었어요.
- 고르기는 dev로만 했어요. held-out은 마지막에 고른 규칙 하나로 한 번만 쟀어요.
- 결론
  - 의미 검색으로 엉뚱한 카드를 거르는 규칙(맞물림 없는 T_HIGH 카드는 근거가 의미 순위 안에 있을 때만)은 dev에서 맞는 카드를 더 많이 버려서 넣지 않았어요(맞음 8 · 일부 3 · 엉뚱 3을 버림).
  - 넣은 것은 '못 받은 카드를 의미 순위로 한 번 더 보기'예요. 모름 끝이 dev 53.7% → 51.4%, held-out 66.1% → 64.0%로 줄었어요.
  - 다만 엉뚱한 카드 답은 줄지 않았어요(held-out 바뀐 답에서 +3). 새로 받은 카드의 엉뚱 비율(dev 15%, held-out 23%)은 원래 카드 답(dev 13%, held-out 무작위 44%)과 비슷하거나 낮아요.

## 1. 바꾼 것

| 파일 | 내용 |
| --- | --- |
| `backend/app/chat/service.py` | `ai_turn`: LLM 모드이거나, 무료 모드라도 `ai_embed_free`이고 키가 있으면 DB 세션을 열기 전에 `embed_query`를 불러요. 실패하면 None → 키워드로만 찾아요. 하루 LLM 상한(`llm_budget_ok`)은 LLM 다시 쓰기에만 그대로 걸려 있어요 |

| `evaluation/v3/coverage_check.py` · `unknown_check.py` | `--dense`: 질문마다 `KB.dense`를 캐시에서 채워요(유료 호출 없음). `unknown_check`는 받은 카드의 맞물림 · 의미 순위도 남겨요 |
| `backend/tests/test_v3_agent_dense_cards.py`(새) | 시험 8개(5장) |

- 확인한 것: 맞물림 덤의 `top`은 `answer.search` → `search3.search(dense=kb.dense)` 결과라, dense가 있으면 이미 키워드 + 의미 검색 RRF 순위예요.
- 오케스트레이터가 나눈 조각 질문도 턴 전체 질문의 의미 순위를 같이 써요(서비스와 같음).

### 2.2 순서 바꾸기(3)를 버린 이유

- 의미 맞물림 덤으로 이미 받을 카드를 밀어내면 엉뚱해지는 경우가 있었어요: '포세린 타일도 미끄럼 방지 타일로 볼 수 있나요?' tile.material.slip → living-room-floor, '도배랑 붙박이장은 어느 쪽을 먼저 해요?' dobae.order.furniture → paint-film.
