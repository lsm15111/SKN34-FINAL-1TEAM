- `APP_ENV`가 `local` · `test`가 아니면 아무것도 만들지 않고 멈춰요(staging · production 시험 있음).
- 업체 6곳은 모두 서울 25개 구를 다녀요(2026-11-20 사용자 요청: 노원 밖 공사에서도 업체가 보이게. 처음엔 노원 · 도봉 · 강북 · 성북 · 중랑 일부만). 그래서 '업체 0곳(C12)'은 서울 밖 구(예: 경기 구리시)에서만 보여요.
- 다시 돌리면 이미 있는 계정은 건너뛰고 아무것도 바꾸지 않아요(공사 · 알림 · 기한 일 그대로). 업체의 다니는 지역만 위 목록에 맞춰요(같으면 그대로). 날짜는 넣은 날 기준(오늘 + N일)이라 며칠 지나면 기한이 지나요. 그때는 빈 DB에 다시 넣어요: `dropdb --force mitjip_v3` → `createdb` → `alembic upgrade head` → `python -m app.demo`(8030을 끄고). 기한 당기기는 공유 DB가 아니라 복사본(`.claude/run-api-copy.sh` · `run-due-copy.sh`)에서 해요.
- 넣을 때 이미 기한이 지난 일은 그 자리에서 거둬요. worker를 켜 두면 기한이 오는 대로 바뀌어요(예: 박요청은 48시간 뒤 답 기한이 지나요).
- 서비스 함수로 넣었어요(가입 · 심사 · 단가 확인 · 요청 · 답 · 고르기 · 실측 · 견적서 · 확정 · 날짜 · 끝냄 · 확인 · 리뷰 · 답글 · 채팅). 직접 넣은 행은 다시 돌릴 때 맞추는 업체 지역(`vendor_areas`)뿐이에요.
- 지난 단계 시각: 서비스는 그대로 부르고, 넣는 동안만 앱 시계를 그 단계 시각으로 옮겨요(`app/shared/clock.py`의 `moved_to`, `APP_ENV` local · test에서만, 그 밖에서는 RuntimeError). DB 기본값 `now()` 칸은 넣는 동안만 ORM으로 넣는 행에 앱 시계 값을 채워요(`demo.py`의 `_fill_now`). 그래서 요청 → 실측 → 견적서 보냄 → 확정 → 날짜 → 끝냄 → 확인 → 리뷰 → 답글이 이야기 순서로 찍혀요. 업체 가입 · 심사 · 단가 확인과 계정 만들기는 넣은 때예요. 앱 시계를 안 쓰는 곳은 아래 '앱 시계를 안 쓰는 곳'에 있어요.
