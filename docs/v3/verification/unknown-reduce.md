# v3 무료 모드 '모름' 답 줄이기 (2026-11-19)

- 대상: `feat-v3-agent-design`(ecfee0b 위 작업 중 사본), 무료 모드만(`LLM_LIVE=false`, `OPENAI_API_KEY=` 비움). 점검 스크립트가 `llm.structured` · `jev_choice` · `embed_query`를 부르면 오류가 나게 막았고 오류는 0건이에요. 유료 호출 0회.
- 지식: 저장소 CSV + v3 지식 요지 색인(`tests/v3_kb.repo_kb`, 조각 2,478) + 카드 416장. `mitjip_rag` DB는 쓰지 않았어요.
- 고르기는 dev로만 했어요. held-out은 마지막에 한 번만 쟀어요(4장).
- 결론: 글자 두 개 묶음으로 맞추는 무료 모드에서는 문턱을 낮추거나 낱말 처리를 바꾸면 엉뚱한 답이 같이 늘어요. 그래서 넣은 것은 정밀도가 확인된 한 가지(관문이 함께 고른 공종의 카드 찾기)뿐이고, 모름은 조금만 줄었어요(전체 58.2% → 56.8%, held-out 66.7% → 66.1%).

## 1. 원인 나누기

### 1.1 '모름'이 나오는 코드 길

`answer.knowledge()`(backend/app/agent/v3/answer.py:145)는 카드 → 조각 문장 → 모름 순서예요. 모름은 두 길이 모두 실패했을 때만 나와요(answer.py:219).

| 유형 | 코드 조건 | 위치 |
| --- | --- | --- |
| card_near: 카드 점수가 문턱 바로 아래 | 1등 카드 열쇠 점수 0.45 이상인데 `(맞물림 and 점수+덤 ≥ T_CARD 0.55) or 점수 ≥ T_HIGH 0.62`을 못 넘음 | answer.py:96-112 |
| trade_filter: 공종 거르기 | 공종을 거르지 않으면 T_HIGH를 넘는 다른 공종 카드가 있음(카드는 `trade + 공통`만 찾음) | answer.py:164-174 |
| policy_no_extract: 정책 질문 | 가격 · 업체 추천 · 브랜드 추천 · 법률 표시가 있으면 조각 문장을 뽑지 않음(정해 둔 글 + 확인할 곳으로 끝남) | answer.py:33 · 189 |
| not_enough: 검색 덮음 부족 | 맨 위 조각이 질문 글자 묶음의 35% 미만을 담음(`hits.enough` 거짓) → 조각 뽑기를 건너뜀 | answer.py:189, bm25.py:17 · 310 |
| extract_low: 조각 문장 점수 미달 | 위 조각 6개의 문장 중 질문 낱말이 50% 이상 든 문장이 없음 | extract.py:25 · 66-100 |
| display_none: 보일 수 없는 출처뿐 | 위 조각이 모두 책 · 품셈(보이지 않음) | extract.py:78 |
| check_drop: 출력 검사 | 검사가 문장을 빼서 묶음이 비었음 | answer.py:86-93 |

- 원인은 모름으로 끝난 `knowledge()` 호출마다 위 표의 순서로 처음 맞는 것 하나로 셌어요(`evaluation/v3/unknown_check.py`의 `cause`). 오케스트레이터가 나눈 질문은 호출이 여러 번이에요.
- '질문에 맞는 자료가 정말 없음'은 코드로 가를 수 없어서 직접 읽어 나눴어요(1.3).

### 1.3 자료가 정말 없나 (dev 모름 30개 직접 읽음)

정책 질문을 뺀 dev 모름 호출에서 무작위로 30개를 뽑았어요. 카드 후보 위 3개와 검색 조각 위 3개를 읽고 나눴어요.

| 판정 | 건수 | 예 |
| --- | --- | --- |
| 맞는 카드 · 문장이 위 3개 안에 있는데 놓침 | 9 | '업체가 공사 날짜를 미루자고 하면'(common.contract.vendor-no-start 0.386), '방문 아래 틈으로 바람이'(mokgong.defect.door-bottom-gap 0.318), '하자 보수 요청은 문자나 메일로'(K20051 문장) |
| 애매(일부만 맞음) | 6 | '천장 몰딩을 떼어 내면'(dobae.order.molding 0.447) |
| 맞는 자료가 없음 | 15 | '줄눈 업체 실수로 문에 흠집, 보상은', '공급면적이랑 전용면적 중 어떤 걸 넣어요', '집 정보 넣을 때 등기부 필요해요' |

- 절반쯤은 자료가 없어서 모름이에요. 맞추기를 고쳐도 줄지 않고 카드 · 조각을 더 만들어야 줄어요(서비스 사용법 질문이 특히 비어 있어요).
- 놓친 9건은 맞는 카드의 점수가 0.3~0.45예요. 같은 점수대의 엉뚱한 카드와 글자 신호로 가를 수 없었어요(2장).

## 2. 시도한 방법 (dev로만 잼)

정밀도는 rag gold 조각(답에 쓴 조각이 gold에 드는 비율)과 **바뀐 답을 직접 읽은 판정**으로 봤어요. gold 세트는 검색용으로 만든 질문이라 실제 질문보다 정밀도가 높게 나와서, 직접 판정을 더 믿었어요.

- 엉뚱한 카드에 붙은 열쇠는 질문과 서술 부분('…은 왜 생겨요', '…해도 돼요')이 같고 대상 낱말이 달라요. 대상 낱말은 열쇠마다 흔해서 TF-IDF 무게가 낮아요. 질문의 드문 글자 묶음이 카드 글에 있는지(조각 IDF · 열쇠 IDF 두 가지)도 재 봤지만, 말투 조각('싶은 · 은데 · 다녀')이 드문 낱말로 잡혀서 맞음과 틀림을 가르지 못했어요.
- 형태소 분석기(Kiwi)는 제품에 넣지 않기로 한 결정(e2_kiwi.py, ADR agent-05)이 있어서 쓰지 않았어요.

## 3. 바꾼 것

| 파일 | 내용 |
| --- | --- |
| `backend/app/agent/v3/answer.py` | `knowledge(…, also=())`: 카드를 `trade + also + 공통`에서 찾아요. 검색 무게는 첫 공종 그대로예요. 함께 고른 공종의 카드면 묶음 공종(`Section.trade`)도 그 공종으로 해요 |
| `backend/app/agent/v3/trade_agent.py` | 공종 담당이 `also=task.trades[1:]`를 넘겨요. 관문이 공종을 둘 이상 골랐는데 한 담당으로 보낸 경우에만 달라져요. 오케스트레이터가 나눈 조각 질문은 공종이 하나라 그대로예요 |
| `backend/tests/test_v3_agent_also_trades.py`(새) | 함께 고른 공종 카드 찾기 · 안 고른 공종은 계속 거름 · '벽지 들뜸'이 필름 카드로 안 감 · 5,000자 입력 5초 안 |
| `evaluation/v3/unknown_check.py`(새) | 원인 나누기 · dev/held-out 따로 숫자 · gold 조각 비율 · 답 문장 저장(`.cache/unknown_rows_<tag>.jsonl`) |
| `evaluation/v3/coverage_check.py` | 행마다 `says_unknown`(화면에 '확인하지 못했어요'가 실제로 나오는가) |

- 새 정규식은 없어요. 카드 파일 · 문턱 값 · 검색 코드는 그대로예요.
- 고르지 않은 실험 코드(낱말 처리 모듈, 카드 찾는 말 파일 읽기)는 지웠어요.
