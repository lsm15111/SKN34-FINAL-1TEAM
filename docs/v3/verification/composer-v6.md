# 작성기 v6 · 설명 질문 일반 설명 섞기 · 우리 집 조건 대략 답 (2026-11-20)

요청
- '인테리어할때 도배 목공 공정이 뭐야 설명해줘'에 두 문장만 나왔어요. ChatGPT처럼 공정마다 하는 일 · 순서 · 고를 것을 알려 줘야 해요.
- 고른 것: 자료 + 일반 설명 섞기 · 설명 질문만 길게(개요 1~2줄 먼저, 나머지는 '자세히 보기') · 우리 집 조건 질문은 대략 예상해서 답하기.

## 1. 원인

| 막던 것 | 자리 |
| --- | --- |
| 공정 개요 카드가 없음(가까운 카드 0.42~0.43 < 0.55) | `answer.knowledge` |
| 질문 낱말이 넓어 검색 위 조각이 표준계약서 · 필름 셀프 · 손상 복구 | `answer.search` |
| 작성기는 근거에 있는 말만 · 첫 문장 40자 · 본문 1~3문장 · '화면 한 칸에 맞게 짧게' | `composer_v5.md` |
| 일반 설명(general_v1)은 아무것도 못 찾은 턴에만 | `turn.py` |
| 일부만 답하면 '실측 때 업체에 물어보시면 정확해요'를 붙임 | `composer.compose` |
| 우리 집 조건 질문은 '집 상태는 직접 봐야 …'만 | `trade_agent` · `templates.MY_HOUSE` |

## 2. 바꾼 것

- `explain.py`(새 파일): 질문 꼴을 코드로 가려요. explain(도배 · 목공의 뜻 · 하는 일 · 순서 · 고를 것 · 방법 · 까닭), house(우리 집 · 오래된 집 + 해야 하나 · 나을까), 그 밖(금액 · 기간 · 업체 · 하자 · 법률 · 위험한 작업)은 지금처럼.
- 공정 정보 근거(코드 데이터, `rule:trade-order` · `rule:trade.dobae` · `rule:trade.mokgong`): 공종 순서, 순서 문장(`ORDER_RULES`), 표준 행 이름(자재 줄 뺌), 상담 때 정하는 것, 실측 때 보는 것, 준비, 주의.
- 지시문 `composer_v6`: 설명 · 우리 집 꼴은 일반 설명(인용 비움)을 섞어요. 설명 꼴은 개요 lead + 공종 블록(`trade` 칸, 제목 '[목공]' · '[도배]'), 블록 6개까지. 우리 집 꼴은 흔한 답 먼저 + 집에서 볼 수 있는 기준 2~3개.
- 코드 검사: 인용을 비운 문장만 일반 설명(`source=general`, 화면 '일반 설명(믿집 자료 밖)')이에요. 숫자 · 업체 · 브랜드 · 하자 · 법률 · 위험한 작업 말은 빼요. 공종 순서 말은 공종 순서 데이터와 맞아야 해요(공정 정보만 인용한 문장도). 인용을 달았는데 안 맞으면 지금처럼 빼요.
- 설명 꼴: 먼저 보인 글이 없으면 개요만 먼저 보이고 나머지는 '자세히 보기'(`brief.lead`). 확인할 곳 줄은 붙이지 않아요.
- 우리 집 꼴: '집 상태는 직접 봐야 …'는 먼저 보이지 않고, 대략 답 끝에 '실측 때 업체에 물어보시면 정확해요' 한 줄. '상태에 따라 달라요' · '상담 때 정해요'만 하는 문장은 빼요. 작성기가 못 쓰면 그 안내를 끝 줄로 둬요.
- 가운뎃점 띄어쓰기를 화면 글과 같게('문선·몰딩' → '문선 · 몰딩').

## 4. 남은 것

- 무료 모드 공정 개요: 공정 정보(코드 데이터)로 정해 둔 개요를 보일지 정해야 해요.
- '오래된 아파트인데 초배 꼭 해야 해?'는 '실크는 초배가 꼭 필요'(K742) 조각이 검색 위에 안 올라 답이 흐려요.
- 개요 lead가 '틀을 잡는다' 대신 '다듬는다'처럼 약하게 쓰일 때가 있어요.
