경계 규칙(라벨 붙일 때 쓴 것)
- 일반 금액 · 시세 · 며칠 걸려요 → `standard_quote`. 업체가 낸 실측 견적서 금액 → `quote_compare`. 업체별 가견적 → `vendor_pick`.
- '견적서'만 있으면: 받은 · 업체 · 두 개 · 비교 · 확정 · 부가세 별도 · 유효기간이 있을 때 `quote_compare`, 그 밖은 `standard_quote`.
- 실측 날짜 · 요청 → `visit`. 공사 날짜 · 공정표 · 연기 · 입주 → `schedule`.
- 하고 싶은 일(공정 · 범위 · 등급) · 범위 안 일 '이것도 해 주나요' → `home_info`. 방법 · 원인 · 증상 → `knowledge`.
- 범위 밖 공정을 해 달라 · 고장 · 증상 → `out_of_scope`. 범위 밖 공정의 '언제 · 무엇 먼저 · 원인 · 뭐가 나아요' → `knowledge`.
- 계약 상식 → `knowledge`, 믿집 안 결제 · 계약 체결 → `out_of_scope`. 업체 고르는 법 → `vendor_pick`.
- 승인하는 말은 그 단계(확정 → `quote_compare`, 연기 수락 → `schedule`, 실측 요청 → `visit`). 기억해 · 지워 → `guide`.
- 두 가지를 따로 물으면 먼저 말한 쪽, 배경 뒤 묻는 말이면 묻는 쪽. held-out에는 그럴듯한 둘째 라벨을 `alt`로 적었어요(81줄).

v3 · v1 라벨과 관계: v1 orchestrator는 금액 → `standard_quote` · 인사 → `guide` · 복합 → 먼저 말한 쪽, trade는 하고 싶은 일 → `home_info` · 증상 → `knowledge`, quote_explanation은 표준견적서 · 가견적 · 실측 견적서에 따라 셋으로, schedule은 그대로, out_of_scope는 계약 상식만 `knowledge`로 옮겼어요.

## 4. 방법

- 기준선(`baseline.py`): `gate.gate(글, has_project=True)` 길 → `step_card` 카드. free_turn과 같아요.
  - `quote_explanation`은 받은 견적서가 있으면 견적서 비교, 없으면 표준견적서라서 정답이 둘 중 하나면 맞은 것으로 쳤어요(기준선에 유리).
  - `multi` → today 카드 · `guide`, `ask_back` → 라벨 없음 · 카드 없음, `trade` → `knowledge`.
- 모델(`train.py`): TF-IDF(낱말 안 글자 2~4개, sublinear) + 로지스틱 회귀(v1 관문과 같은 꼴). scikit-learn 1.9.1은 학습에서만 써요(`uv run --with scikit-learn`, 의존성 안 더함).
  - 고르기는 dev 5겹 교차검증 macro-F1만 봤어요: C=3 · 무게 없음(0.779). 비교: 선형 SVM 0.773 · 낱말 + 글자 0.743.
  - 온도 보정: 겹 밖 점수로 음의 로그 우도가 가장 작은 T=0.3219(dev 겹 밖 ECE 0.395 → 0.051). 가장 높은 라벨은 그대로예요.
  - 기준값: 겹 밖 예측을 '기준값 아래는 옛 기준선 길'로 섞었을 때 카드 정답률이 가장 높은 0.2(dev 79.4% vs 옛 기준선 45.1%). 사실상 늘 모델 라벨을 써요.
  - 내보내기: 특징 13,578개 · 338KB, checks 18줄(dev 글, 학습 쪽 확률). 추론(`intent_v4.probs`)은 순수 파이썬이고 checks와 1e-5 안에서 같아요(테스트).
- 지표(`metrics.py`): macro-F1(9라벨 평균) · 라벨별 P · R · F1 · 범위 밖 재현율 · 카드 정답률(고른 카드가 정답 라벨의 카드와 같음, 지식 · 범위 밖은 '카드 없음') · ECE(같은 폭 10구간) · 기준값 곡선. 구간은 항목을 다시 뽑는 부트스트랩 2,000번(씨앗 20261121)이고, 두 방식 차이는 같은 표본으로 쟀어요.
- held-out은 고르기에 쓰지 않았고 `evaluate.py --final`로 한 번 쟀어요(같은 모델로 다시 돌려도 숫자는 같아요).

### 5.5 속도 · 크기

- 한 문장 추론: 중앙값 0.06~0.23ms · p95 0.11~0.55ms(held-out × 5번을 4번 잼, 다른 작업과 같이 돈 기계라 흔들려요). 옛 관문 한 번은 중앙값 0.22~0.27ms예요.
- 모델 읽기 30~110ms(프로세스마다 처음 한 번) · 파일 338KB · 특징 13,578개.

### 5.6 자주 틀린 것

- knowledge 재현율 0.47이 가장 큰 구멍이에요(138줄 중 73줄을 다른 라벨로).
  - → out_of_scope 27: 다른 공정의 시기 · 원인 질문('욕실은 언제쯤 하면 돼요?'). 둘 다 카드가 없어서 카드 정답률에는 영향이 없어요.
  - → home_info 16 · standard_quote 12: '몰딩 교체는 언제 해요?' · '몰딩 교체하고 도배도 하려는데 순서는?'처럼 공정 낱말 + 시기 질문.
- '고마워요.' · '오늘 날씨 어때?' · '오늘 점심 뭐 먹지?'를 틀렸어요. held-out과 거의 같은 dev 줄을 모두 빼서 이런 흔한 짧은 말을 학습에서 못 봤어요(held-out 값이 보수적인 까닭 하나).
- '견적서'만 있는 일반 질문(표준견적서 정답)을 quote_compare로 6줄 보냈어요.

## 6. 한계

- 라벨은 한 사람(이 역할)이 붙였어요. 경계가 애매한 81줄에 `alt`를 적었지만 두 사람 일치도(κ)는 못 쟀어요.
- dev의 82%가 합성이에요(같은 계열 모델이 씀). dev 교차검증 0.78 vs held-out 0.60으로 글 모양 차이가 커요.
- held-out은 다른 목적으로 만든 세트를 모은 것이라 지식 질문이 41%예요. 실제 무료 모드 말 분포가 아니에요. visit 16 · home_info 17 · 범위 밖 24줄이라 구간이 넓어요(범위 밖 재현율 34.6~75.0%).
- held-out을 한 번 봤으니, 이 결과를 보고 고친 다음 판은 새 held-out(예: 시나리오 판 2 새 대본, 질문 은행 표본)으로 재야 해요.
- 한 문장만 봐요. 앞 대화가 필요한 말(11줄)은 무료 모드도 지금은 못 봐요.
- 업체 화면 무료 모드는 길과 상관없이 요청 브리핑 카드라서 업체 말 결과는 참고예요.
- 옛 기준선은 quote_explanation을 유리하게 셌어요(실제 v3 관문 길은 상태에 따라 둘 중 하나만 맞아요).
- 길 비교는 카드 종류만 봐요. 상태에 따라 카드가 비는 경우(업체 · 견적서 없음)와, 답 글이 말한 카드를 더하는 `fit_cards`는 흉내 내지 않았어요. 답 글의 질은 시뮬레이터 · 판정으로 따로 봐야 해요.
