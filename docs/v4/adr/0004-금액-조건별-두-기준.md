# ADR 0004: 표준견적서 도배 금액은 공사 조건별 두 기준으로 센다

- 상태: 결정(2026-11-21)
- 결정한 사람: 사용자(조건별 두 기준 · 값) → 계산 엔진 담당(고르는 규칙 · 줄 키 · 판)

## 맥락
- 지금 표준견적서(판 `2026H2-rooms`)는 두 시장에 한 값을 써요.
  - 서울 리모델링 업체 실견적 235건(전체 철거 묶음)의 0.57배예요(MdAPE 43.2%).
  - 시장 도배 견적(서울12호 밖 실크 336건)과는 0.98배로 맞아요.
  - 합지는 시장의 1.61배예요. 합지 시공비를 실크와 같이 써서예요.
- 서울12호는 시장 실크 619건 중 상위 3%예요. 한 값으로 둘 다 맞출 수 없어요.
- 근거(집계만 옮김)
  - `d10-/reports/v4 비서 에이전트/quote-accuracy/README.md`: 보정안 P3
  - `d10-/data/price-sources/README.md`: 추천안 R

## 결정
### 1. 두 기준 = 두 단가 판 (`refprice/book.py`)

| 항목 | 도배만 하는 공사 기준 | 리모델링 기준 |
| --- | --- | --- |
| 코드 · 판 | `paper_only` · `2026.11-market` | `remodel` · `2026.11-remodel` |
| 출처 이름 | 시장 실견적 가운데(8출처 619건, 2026-11) | 서울 업체 실견적 보정(2026-11) |
| 벽 · 천장 시공(원/㎡) | 공공 5,993 · 8,531 | 품 × 일당 30만: 7,200 · 10,530 |
| 합지 시공비 | × 0.55 | × 0.55 |
| 벽지 소요량(도배 면적 ×) | 실크 1.248(1.2 × 1.04) · 합지 1.2 | 1.58 |
| 부자재(초배지 줄 대신, 원/공급 평) | 실크 6,900 · 합지 3,300 | 16,000 |
| 퍼티(원/공급 평) | 14,264 · 선택 | 20,000 · 포함 |
| 식대 | 줄 없음(일당에 포함) | 15,000 × 품 · 포함 |
| 운송 · 경비 | 운송 · 경비 5만 원 · 선택 | 운송비 3만 원 · 포함 |

- 사용자 말과 다른 값은 README를 따랐어요.
  - 합지 부자재 3,300원, 실크 벽지 × 1.04, 퍼티 14,264원, 경비 5만 원(R)
  - 리모델링 기준의 합지 시공비도 × 0.55(price-sources 결론 4: "어느 안을 고르든")
- 품 · 기간은 두 기준 모두 표준품셈 그대로예요. 공정표는 바뀌지 않아요.

### 2. 고르는 규칙 (`calc.dobae.pick_profile`, 순수 함수)
- 입력: 공사에 고른 목공 항목(`trades.mokgong.items`) + 모은 조건(`project_conditions`, 0038)
- 아래 중 하나라도 있으면 리모델링 기준, 없으면 도배만 하는 공사 기준

| 신호 | 모은 조건(단추 글) | 없을 때 보는 목공 항목 |
| --- | --- | --- |
| 문틀 교체 | `mokgong.doors` = 문틀까지 (문짝만이면 아님) | `door` |
| 몰딩 교체 | `mokgong.molding` = 바꿔요 (그대로 둬요면 아님) | `molding` |
| 천장 평탄화 | `mokgong.ceiling` = 네 (아니요면 아님) | `flatten` |
| 전체 새로 | `mokgong.molding_scope` = 벽 · 천장까지 새로 | 없음 |

- `mokgong.molding_scope`가 '도배만 새로' · '몰딩 색만 바꾸기'면 몰딩 교체로 보지 않아요.
- 모은 조건이 '아직 몰라요'이거나 단추 글이 아닌 답이면 목공 항목을 봐요.
- 걸레받이만 바꾸는 집, 손님 계산, 평수만 물은 질문, 업체 단가표 예시는 도배만 하는 공사 기준이에요.
- 전체 철거는 지금 받는 칸이 없어요(집 정보 · 공정 · 모은 조건 어디에도 없음).
  - '벽 · 천장까지 새로' 답을 전체 철거 · 큰 공사 신호로 봐요.
  - 철거 칸이 생기면 같은 표에 한 줄 더해요.
- 단추 글이 되묻기 칸(`agent/v3/trades.py`)과 같은지 테스트가 봐요.

### 3. 줄과 판 고정
- 새 표준 행 키: `material`(초배지 대신) · `putty` · `meal` · `truck`
  - 가견적 v3 줄(1205 · 1201 · 1207 · 1208)과 같은 키예요.
- 포함 상태: 도배만은 퍼티 · 운송 · 경비가 '선택'(합계 밖), 리모델링은 모두 '포함'이에요.
- 줄 이름 끝 괄호가 짧은 뜻이에요(지금 '(풀 포함)'과 같은 꼴).
  - 예: '부자재 (풀 · 부직포 · 네바리 · 실리콘 등)'
  - 리모델링 시공 줄은 '(인건비)'예요. 풀은 부자재 줄에 있어요.
- 판 고정
  - 고른 기준의 판을 `standard_quotes.price_ver`에 저장해요.
  - 모은 조건이 바뀌어 기준이 바뀌면 새 버전을 쌓아요.
  - 이미 만든 견적(`2026H2-rooms`)은 줄 · 금액을 그대로 둬요.
  - 산식 버전(`2026.11.2`)은 그대로예요. 공정표가 다시 계산되지 않게 판으로만 가려요.
- API: `StandardTradeOut` · `GuestStandardOut`에 `profile` · `profile_name`을 더했어요.
- 가견적 비교 %: 그 집 판으로 표준견적서를 다시 세고, 합계에 든 줄만 견줘요.
  - 리모델링 기준이면 퍼티 · 식대 · 운송비도 비교에 들어가요.

## 결과
- 리모델링 기준 vs 서울12호(시험 78건)
  - 중앙 비율 0.574 → 0.991
  - MdAPE 42.6% → 7.2%
  - ±20% 0% → 97.4%
- 서울12호 235건 전체: MdAPE 43.2% → 6.7%
- 규칙이 서울12호 글을 리모델링으로 고른 비율: 228/235(97.0%)
  - 글 상세 줄의 문틀 · 몰딩 · 천장 신호를 목공 항목 · 모은 조건으로 옮겨 넣었어요(가정).
  - 놓친 7건은 문틀 · 몰딩 교체 금액 줄이 없는 글이에요(문선 · 경첩 · 걸레받이만). 7건 모두 전체 철거라 철거 칸이 생기면 잡혀요.
  - 규칙대로 고른 기준으로 재면 235건 MdAPE 6.9%, 시험 78건 7.2%예요.
- 도배만 하는 공사 기준 vs 시장(서울12호 밖)
  - 실크 336건: 0.978 → 1.055, MdAPE 12.7% → 13.4%
  - 합지 90건: 1.608 → 1.082, MdAPE 60.8% → 11.7%
- 좋음
  - 큰 공사는 서울 업체 수준, 도배만은 시장 가운데로 따로 맞아요.
  - 합지 과대 견적이 풀려요.
- 비용
  - 몰딩만 바꾸는 집도 리모델링 기준이에요(서울12호 밖 자료로는 못 잼).
  - 리모델링 값은 업체 한 곳이에요.
  - 다른 열린업체 자료가 생기면 다시 맞춰요.
