### 2.3 뒤로 가기 · 새로 고침 · 공유 링크

- **뒤로 가기**: 대화에서 연 카드는 `router.back()`으로 닫혀서 대화 스크롤이 그대로예요. 링크로 바로 들어와 앞 기록이 없으면 닫기는 `router.replace('/projects/{id}')`예요. 서랍 안 사진(`?photo=n`)은 v3처럼 얕게 붙여 뒤로 가기로 닫혀요. 해시(`#`)는 쓰지 않아요.
- **새로 고침**: 대화는 서버 기록(**(새)** `GET /assistant/feed`)으로 다시 그려요. 처음 30개, 위로 올리면 더 읽어요. 카드는 메시지에 값을 굳히지 않고 열 때마다 기능 API를 다시 읽어요(승인 카드만 사람이 본 값을 고정). 열려 있던 카드는 주소대로 다시 열려요. 쓰다 만 입력 글만 브라우저에 둬요(편의).
- **공유 · 알림 링크**: `notify/catalog.py`의 링크(`/projects/{pid}/quotes` 등)가 그대로 그 카드를 열어요. 남의 공사는 404(C56), 로그인 전이면 로그인 뒤 같은 주소로 돌아와요(`next`).
- **실시간**: 지금 `/stream`(LiveProvider)으로 소식이 오면 그 카드만 다시 읽어요. 새 카드가 생기면 대화 맨 아래에 붙고, 위를 보고 있으면 '새 소식 ↓' 단추만 떠요.

### 2.4 처음 오는 길

- `/` [시작하기] → `/start` 첫 대화(로그인 없이) → C1 집 정보 → C2 표준견적서(`POST /guest/standard`) → 가입 카드(가운데) → `POST /projects` → `/projects/{id}`로 이어져요.

## 3. 단계별 카드 명세 (c)

공통 규칙
- 금액 · 날짜 · 기간은 API(계산 엔진) 값만 보여요. 화면 · 비서 · 지시문은 계산하지 않아요.

- 카드 글은 '-해요'체이고 영어 상태값을 보이지 않아요. 칸 아래 도움말 · 저장 안내 · 요약 줄은 기본으로 넣지 않아요.
- 묶음마다 출처 이름표를 붙여요: '믿집 계산'(계산 엔진) · 'AI 답변'(LLM 글) · '믿집 안내'(정해 둔 글). LLM이 실패하면 계산 결과만 보이고 "설명을 만들지 못했어요"라고 써요.

## 4. 비서 카드 공통 컴포넌트 (d)

### 4.1 상태 표시 `StatusTag`

v3 N4 C 규칙(아이콘 + 글자, 색은 작은 아이콘에만)을 따라요. 글자는 `--mj-text-sub` 13px 굵게예요.

| 상태 | 아이콘 | 색 토큰 | 글자 |
| --- | --- | --- | --- |
| 작업 중 | 도는 원 | `--mj-st-todo` | 작업 중 |
| 기다리는 중 | ○ | `--mj-st-wait` | 기다리는 중(+ 기한) |
| 완료 | ✓ | `--mj-st-ok` | 완료 |
| 실패 | ! | `--mj-st-late` | 실패 |
| 취소 | – | `--mj-st-done` | 취소 |
| (승인 카드만) 내 차례 | ● | `--mj-st-todo` | 승인이 필요해요 |

### 4.2 작업 카드 `TaskCard`

- 모양: 머리(상태 + 제목 + 시각) · 줄(업체별 상태와 한 줄 사실) · 꼬리(`자세히 ›` + ⋯ 메뉴).
- 비서가 시작한 일(요청 보내기 · 단지 찾기)과 그 뒤 기능 상태(업체 답 · 견적서)를 한 카드에서 보여요. 상태는 기능 API · `/stream`에서 다시 읽어요.
- 피클 규칙: 앱을 닫아도 일은 계속돼요(다음에 열면 결과). 같은 오류로 두 번 실패하면 멈추고 알려요. 고객이 취소한 일은 다시 시작하지 않아요. 실패를 숨기지 않아요.

### 4.3 승인 카드 `ApprovalCard`

```
┌──────────────────────────────────────────┐  ← 파란 고리(--mj-primary 1.5px)
│ ● 승인이 필요해요                 내일 18:00까지 │
│ 결도배로 확정                                 │  제목 = 무엇을
│ ▲ 1판보다 +110,000원  4,180,000원 → 4,290,000원 │  차액 줄(바뀐 때만, 맨 먼저)
│ 4,290,000원  부가세 포함                       │  얼마에(28px 굵게)
│ 견적서  2판 · 11월 22일 받음 · PDF            │  어느 버전
│ 공사 기간 2일 · 유효기간 12월 31일까지          │
│ ⓘ 다른 두 곳 요청은 닫혀요                      │  그 뒤 일(한 줄)
│ [ 결도배로 확정 ]   거절                        │  단추 이름 = 동사
└──────────────────────────────────────────┘
```

- 상태 흐름: 승인 기다림 → 작업 중 → 완료('확정했어요 · 11:42' + 결과 링크) / 거절('거절했어요' + [다시 만들기]) / 만료 / 바뀜(409: 새 값 + 차액으로 다시 그림) / 실패(오류 글 + [다시 해 보기]).
- 규칙
  - 되돌릴 수 없는 일은 모두 서버 대기 행동 하나로만 실행돼요. 전체 화면 카드 안의 [확정]도 같은 승인 카드를 가운데 창으로 띄워요(길이 둘이 되지 않게).
  - 멱등 키(`client_key`)와 본 버전(`seen_ver` · `seen_version` · 동의 문구 판)을 같이 보내요. 다르면 409 → '바뀜'.
  - 같은 종류는 하나만 살아 있어요. 새 카드가 생기면 옛 카드는 '새 카드로 바뀌었어요'로 접혀요.
  - 누르면 바로 단추를 끄고(`aria-busy`) 카드 안에서 결과를 보여요. 따로 확인 창을 겹치지 않아요(카드가 확인 단계예요).
  - 거절은 회색 글자 단추. 거절한 제안은 3일 동안 다시 띄우지 않아요.
- 실행 API(새): `POST /assistant/actions/{aid}/approve {client_key, seen}` → 기능 service의 공개 함수(위 C3~C6 실행 줄). `POST /assistant/actions/{aid}/reject`.

### 4.4 제안 카드 `SuggestCard`

- 모양: ✦ + '제안' 이름표 · 한 줄 제안 · 근거 한 줄(코드 사실) · [해 볼게요] [괜찮아요].
- 누르면 채팅으로 이어지거나(피클 '둘러보기' → 채팅) 승인 카드를 만들어요. 한 턴에 하나, 하루 상한.

### 4.5 오늘 정할 일 `TodayCard`

- 모양: 날짜 · 제목 '오늘 정할 일 n' · 줄(아이콘 · 할 일 · 기한 · 단추) · 묶음(정할 일 · 기다리는 일 · 밤사이 소식 · 알아 두기).
- 비서 말(문장 하나, AI)은 카드 위 말로 따로 둬요. 카드 안 줄은 모두 코드 사실이에요.

### 4.6 알림(종)

- 머리 오른쪽 44px 단추 + 안 읽은 수(`--mj-count`). 웹은 370px 펼침(`--mj-drop-w`), 폰은 `/notifications`.
- 줄: 종류 아이콘 · 글(`notify/catalog.py` 문구) · 시각 · 안 읽음 점. 누르면 그 경로(= 그 카드)로 가요. [모두 읽음] `POST /notifications/read-all`.
- 상태가 바뀌면 알림 한 건 + 대화 카드 하나가 같은 `dedup_key`로 와요. 문자 · 메일은 보내지 않아요.

### 4.7 그 밖의 작은 조각

- **정한 것 줄**(다시 묻지 않기): '벽지는 실크로 정했어요 · 바꾸기'. 비서는 정한 것을 다시 묻지 않고 까닭만 짧게 말해요.
- **기억 칩**: 보드 '비서가 기억하는 것'(사용자 말에서만, 근거 메시지 링크, × 지우기). 건강 · 연락처 · 금액은 저장하지 않아요.
- **출처 이름표**: '믿집 계산' · 'AI 답변' · '믿집 안내'.
- **날짜 줄 · 새 소식 ↓ · 지난 단계 접기**: 지난 단계 카드는 한 줄 요약('표준견적서 · 3,148,560원 · 11.14 ›')으로 접혀요.

## 5. 업체 화면 (e)

### 5.1 방향(D3 추천: 작업함 + 비서 카드)

- 업체는 여러 고객의 요청을 한꺼번에 다뤄요. 그래서 대화 한 화면 대신 지금 구조(작업함 → 요청 하나 → 견적서 → 공사 한 건)를 두고, 그 위에 v2 시각 언어와 비서 카드를 입혀요.
- v2 시각 언어 입히기
  - 머리: v2 머리 + '업체' 알약 + 업체 이름 + 종.
  - 작업함: v2 `.tabs` 알약 탭(할 일 · 기다림 · 일정 · 공사 · 끝남, 수 붙임) + 줄 카드(`.mc-card` 모양: 동네 · 면적 · 상태 · 기한). 웹은 목록 400 + 오른쪽 자세히 2단, 폰은 목록 → 자세히.
  - 요청 하나: 맨 위 V1 브리핑 카드, 그 아래 단계 띠(기간 답하기 · 날짜 확정 · 실측 · 견적서 · 확정), 사진, 달력.
  - 같은 조각을 써요: `StatusTag` · `TaskCard` · `ApprovalCard` · `SuggestCard` · 오늘 브리핑(작업함 맨 위).
- 비서에게 묻기(업체용 대화)는 나중 단계예요: 웹 오른쪽 칸 · 폰 시트. 지금 `/ai/turns`는 고객만 써요.

### 7.3 그 밖의 위험 · 확인할 것

- D1 토큰을 바꾸면 'v2 모양'이 조금 달라 보여요(파랑이 더 진하고 회색이 차가워져요). 시안으로 사용자 확인이 필요해요.
- AGENTS와 다른 점(팀 확인 · ADR): 실측 날짜를 다룸(1절), 새 이름 `assistant`(1 · 2장), 화면 영역 `assistant` 더하기(2장), 업체 확정 · 공정표 확정을 '대기 행동'으로 감쌈(3장 '사람이 누른 요청'은 그대로 지켜요).
- C1 바깥 API(data.go.kr · 도로명주소 키)가 없으면 막혀요 → 직접 넣기 길을 기본으로 둬요. 새 외부 서비스는 이슈로 먼저 알려야 해요.
- C3 '업체별 연락처 보내기 동의'는 v3가 쓰지 않던 칸(`share_contact_ids` · `consent_ver`)을 다시 써요. v3는 실측 확정 뒤 채팅으로만 이었어서, 동의 문구 · 보관 기간을 팀 · 법무와 다시 맞춰야 해요.
- LLM 실패 · 비용: 카드가 LLM 문장에 기대지 않게 그려요(문장 없이도 완결). 오늘 정할 일 문장은 하루 상한 안에서만.
- 폰 아래쪽 겹침: 입력 칸 · 아래 단추 띠 · 탭 바 · 안전 영역. 대화 화면은 탭 바를 숨기고, 전체 화면 카드는 입력 칸을 숨겨요.
- 접근성: 대화 목록 `role="log"` + `aria-live="polite"`는 새 메시지에만. 카드가 열리면 제목으로, 닫히면 연 단추로 초점을 돌려요.
