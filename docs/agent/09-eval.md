# 09. 평가 — 세트 · 지표 · 도구

AGENTS.md §4의 eval 세트(공정표 15 · 의도 200 · RAG 30 · 상담 10 · 오케스트레이터 30 · 가이드 50 · 견적 설명)를 그대로 두고 **무엇을 어떻게 재는지**를 정한다. dev와 held-out은 2:1. 근거: [T6 5장](../research/T6_agent_tech.md), [T7 2장](../research/T7_voc_competitors.md).

## 1. 두 층

| 층 | 언제 | LLM 호출 | 무엇 |
| --- | --- | --- | --- |
| L0 CI | PR마다 | 0회 | 분류기 지표 · 검색 지표 · 공정표 정확 일치 · 숫자 검사기 단위 테스트 · 오케스트레이터 경로(ScriptedModel) |
| L1 야간 · 수동 | 프롬프트를 바꾼 PR(`prompt` 커밋)마다 + 주 1회 | 있음 | 상담 · 가이드 · 견적 설명 품질을 루브릭으로 판정(promptfoo), 결과 JSON을 저장소에 남겨 회귀 비교 |

- **OpenAI Evals 플랫폼은 쓰지 않는다**(2026-10-31 읽기 전용, 11-30 종료 — 공식 문서 확인). 공식 이전 경로도 promptfoo다.
- 판정 모델은 생성 모델과 다르게: 생성 `gpt-6.1-terra`, 판정 `gpt-6.1-sol`. 같은 과제를 3번 돌려 모두 통과해야 통과(pass^3).
- 사람 라벨 20~30개로 판정 모델과의 일치도(Cohen's κ)를 잰다.

| `rag` | 30 | 지식 검색 | Recall@5, nDCG@10, MRR. 벡터만 / bigm만 / RRF / RRF+재순위 비교 | Recall@5 ≥ 0.90 | L0 |
| `rag`(답) | 30 | 근거 일치 | 주장마다 인용 조각이 뒷받침하는 비율 | ≥ 0.95 | L1 |
| `schedule` | 15 | 일정 계산 · 제약 변환 | 날짜 · 선후 · 겹침 없음 **정확 일치**, 말 → 제약 변환 일치 | 15/15 | L0(계산) · L1(변환) |

## 3. 가이드 · 코치 루브릭 (항목별 0/1)

1. 질문의 답이 첫 문장에 있다.
2. 사실이 인용한 지식 조각 · 용어집과 맞다(근거 없는 주장 0개).
3. 새 용어가 3개 이하이고 쉬운 말로 풀려 있다.
4. 고객 단계(견적 전 · 업체 고르기 · 실측 · 공사 D-n)에 맞다.
5. 확인 질문이 있으면 1개이고 답이 분명하다.
6. 선제 팁이 있으면 1개이고 지금 단계와 이어진다.
7. 금액이 없다(금액은 견적 설명 · 계산 엔진). 지식 숫자는 인용 조각에 있는 값만.
8. 업체 비방 · 법률 단정 · 안전 단정이 없다. 출처끼리 다른 값(상충)은 상충이라고 밝힌다.

**골든 요점 12개**(T7 2.3)를 가이드 50의 정답 체크포인트로 쓴다. 예: G1 실크 vs 합지 — 소재(PVC 코팅 vs 종이) · 시공(초배 · 띄움 vs 겹침) · 이음매 · 물걸레 관리 · 가격 차는 범위로 · 선택 기준(거주 기간 · 아이 · 벽 상태 · 예산) · 기존 실크는 철거 필요 / 하면 안 되는 것: 금액 단정.

## 4. 의도 라벨 — 두 층

- **경로 라벨 12종**(03 문서 3절)으로 분류기를 학습 · 평가한다.
- **주제 태그 30종**(T7 2.1: `guide.start` … `abuse.harm`)은 받은 에이전트가 붙이고 분석 · 가중치에만 쓴다. 분류기 학습 단위를 30종으로 두면 200개 평가 세트에서 클래스당 표본이 너무 적다.
- 경계 규칙(T7): 화장실 **문** 교체는 목공, 욕실 타일 · 도기는 범위 밖. 몰딩 · 문 '필름 vs 교체'는 목공으로 답하되 필름 시공은 범위 밖임을 밝힌다. '도배 대신 페인트' 비교는 도배 자재 질문으로 짧게.
- 학습 데이터와 평가 데이터를 섞지 않는다. 의도 200은 **평가 전용**. 학습용은 경로당 50~150문장(총 1~3천)을 실제 문장 · 팀 작성 · LLM 패러프레이즈(사람 검수)로 만든다.
- 변형: 존댓말 · 반말 · 오타 · 축약, 평형(24 · 32 · 34평), 범위(거실만 · 전체), 천장 포함 · 제외, 거주 · 공실 슬롯을 바꿔 3~5배.

## 5. 파일 형식 (`evaluation/<세트>/`)

```
evaluation/intent/dev.jsonl        {"id":"Q001","text":"...","route":"coach","topic":"guide.start","freq":"high","note":"평형 · 공정 범위 되묻기"}
evaluation/intent/heldout.jsonl    같은 형식, dev:heldout = 2:1, 경로별 층화
evaluation/guide/dev.jsonl         {"id":"G1-1","question":"...","stage":"before_quote","must":["...","..."],"must_not":["금액 단정"],"golden":"G1"}
evaluation/consult/dev.jsonl       {"id":"C01","trade":"dobae","turns":[{"user":"..."}],"expect_slots":{"wall_removal":"after_visit"}}
evaluation/orchestrator/dev.jsonl  {"id":"O01","text":"...","expect":{"route":"both","agents":["mokgong","dobae"],"max_subcalls":3,"ask_back":false}}
evaluation/rag/dev.jsonl           {"id":"R01","query":"...","relevant":["kc:dobae.silk_removal","kc:..."]}
evaluation/schedule/dev.jsonl      {"id":"S01","input":{...},"expect":{"days":[...]}}
evaluation/quote_explanation/      시나리오 폴더: 입력(표준 · 가견적 · 실측 · 사유 코드) → 기대 브리지 · 금지 숫자
evaluation/run.py                  세트 이름을 받아 L0 지표를 계산하고 결과를 evaluation/results/<세트>-<날짜>.json에 쓴다
```

## 7. 기록과 회귀

- 결과 JSON에 모델 이름 · effort · 실행일 · 프롬프트 버전 · 데이터 버전을 남긴다. `gpt-6.1-terra`는 날짜 스냅샷이 없어 같은 이름이라도 동작이 조용히 바뀔 수 있기 때문이다.
- 프롬프트를 바꾸는 PR은 커밋 type `prompt`, PR 본문에 L1 결과 표(전 · 후)를 붙인다(AGENTS.md §4).
