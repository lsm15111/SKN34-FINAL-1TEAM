# 01. 작업 지도 — 작업마다 무엇이 맡나

반셀프 여정의 작업을 하나씩 놓고 **코드 · 계산 엔진 · 학습 모델 · LLM 워크플로 · LLM 에이전트 · 사람 버튼** 중 무엇이 맞는지 정했다. 에이전트는 "꼭 필요한 곳에만" 둔다.

## 1. 판단 기준

| 작업 성격 | 맡는 것 | 근거 |
| --- | --- | --- |
| 규칙이 분명하고 결과가 하나(금액 · 날짜 · 판정) | **계산 엔진 · 코드** | AGENTS.md §3, OpenAI *A practical guide*: 결정적 해법으로 충분하면 에이전트를 쓰지 않는다 |
| 라벨이 정해진 분류이고 학습 데이터를 만들 수 있음 | **직접 학습한 분류 모델** | 지연 · 비용 · 보정 가능(T6 6장) |
| 비정형 말을 이해 · 생성하지만 단계는 정해져 있음 | **LLM 워크플로**(한 번 호출 · prompt chaining · routing) | Anthropic *Building effective agents*: workflow부터 |
| 대화 중 되묻고 도구를 골라야 함 | **LLM 에이전트**(도구 ≤ 4, 호출 상한) | 같은 글: 경로를 미리 못 정할 때만 agent |
| 돈 · 확정 · 승인 · 남에게 보내기 | **사람 버튼** | AGENTS.md §3 "사람이 누른 요청으로만" |
| 사진 · 문서 이미지 | **비전 LLM + 사람 확인** | DefectBench 2026: 개수 · 위치 · 얼룩은 약함(T6 8장) |

## 3. 결과: 무엇이 에이전트인가

- **LLM 에이전트 4개**(도구 루프): 코치 · 목공 서브 · 도배 서브 · 공정표
- **LLM 워크플로 2~3개**(정해진 단계): 견적 설명 · 사진 판독(선택) · 분해기(선택)
- **학습 모델 1개**: 입구 분류기(+ Jev 보조)
- 나머지(금액 · 날짜 · 범위 · 판정 · 카드 고르기 · 추천 · 검사 · 저장)는 **코드와 계산 엔진**

## 4. '다중 에이전트'가 드러나는 곳 (발표 · 평가용)

| 요구 | 믿집에서 |
| --- | --- |
| 라우팅 | 입구 관문(분류기 → Jev → 되묻기) |
| 병렬 | 두 공정 질문에서 목공 · 도배 서브를 동시에, 결과를 한 카드로 |
| 취합(aggregation) | 오케스트레이터가 목공 → 도배 순서로 질문 묶기 · 섹션 합치기 |
| 검증 루프(verification loop) | 숫자 슬롯 + 문장 숫자 검사 → 실패 시 1회 재생성 → 그래도 실패면 계산 결과만 |
| 하네스 루프(harness loop) | 에이전트별 도구 ≤ 4회 · 턴당 하위 호출 ≤ 3 · 일일 토큰 상한 |
| MCP | 일정 MCP 서버(2026-07-28판, 내부 JWT, 본인 프로젝트만) |
| 그래프 성격 지식 | 공정 선후 DAG(재귀 CTE) · 변경 규칙 — 그래프 DB 없이 PostgreSQL로 |

- SKN34 강사 요구사항 원문은 아직 못 봤다(SKN29 문서 기준 기억). 원문을 받으면 이 표를 다시 맞춘다.
