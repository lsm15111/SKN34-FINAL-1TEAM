# 02. 에이전트 명세

각 에이전트가 **무엇을 받고, 무엇을 쓸 수 있고, 무엇을 돌려주고, 무엇을 하면 안 되는지**를 정한다. 실행 방식은 [03 실행 구조](03-runtime.md), 작업별 판단 근거는 [01 작업 지도](01-tasks.md).

## G. 입구 관문 (`agent/gate.py` · `intent.py` · `route.py`)

- **입력**: 문장(전화번호 · 동호수 가림), 화면 위치(어느 페이지에서 물었는지), 프로젝트 유무.
- **출력**: `GateResult{route, topic?, confidence, method(rule · model · jev · ask), ask_choices?[]}`
- **분류기**: 1단계 임베딩(multilingual-e5 또는 KURE-v1) + 로지스틱 회귀(기준선, 학습 몇 초). 목표에 못 미치면 `skt/A.X-Encoder-base`(Apache-2.0) 또는 `klue/roberta-base` 미세조정. 온도 보정 후 경로별 임계값. ONNX int8 CPU 서빙.
- **Jev**: τ 미만일 때 1회만. 결정 모델이라 답 글을 쓰지 않는다. 한국어 지원이 문서에 없어 의도 200 세트로 재고 채택(떨어지면 `gpt-6-luna` enum 분류).
- **금지**: 답변 생성, DB 접근.
- **평가**: `intent` 200(09 문서).

## O. 오케스트레이터 (`agent/orchestrator.py`)

- **입력**: `GateResult`, 턴 컨텍스트(03 문서 2절 3번).
- **하는 일**: 단일 경로 실행 / `both`면 목공 · 도배 서브 병렬 → 목공 → 도배 순서로 한 카드 / 다중 경로면 공정 → 견적 → 일정 순서로 최대 3개 / 하위 호출 3회 상한 / 결과 합치기 · 출력 검사 호출.
- **분해기(선택)**: `unclear`인데 의도가 여럿으로 보일 때 1회. 출력 `[{route, sub_question}]` ≤ 3.
- **금지**: 하위 결과를 LLM으로 다시 요약하지 않는다(합치기는 템플릿). 상한을 넘겨 부르지 않는다.
- **평가**: `orchestrator` 30(경로 · 도구 순서 · 상한).

## 2. 공정 에이전트 (`agent/trade_agent.py`, 코드)

- 문장 · 화면에서 공정을 고른다: 경로가 `dobae`/`mokgong`이면 그대로, 화면이 공정별 페이지면 그 공정, 공정 낱말(몰딩 · 걸레받이 · 문 · 천장 · 벽지 · 실크 …)로 판별. 모르면 되묻기("도배 · 목공 중 어느 쪽이에요?").
- 프로젝트 정보 · 표준견적 줄 · 예상 범위 · 브리프는 **코드가 먼저 읽어** 서브에이전트에 넘긴다.
- 범위 밖 공정의 서브에이전트는 만들지 않는다(AGENTS.md §4).

## 3. 견적 설명 (`agent/quote_explanation_agent.py`)

**prompt chaining + 코드 게이트.** 금액은 하나도 만들지 않는다. 계산 엔진이 만든 값의 **이유**만 쓴다.

```
[코드] 계산: 표준 줄 · 범위(폭의 몫) · 가견적 · 실측 견적 · 차이 브리지(06 문서 6절) · 누락 체크(T7 3.3)
  → [LLM] 설명 초안(슬롯만) → [코드] 숫자 · 스키마 검사 → (실패 시 1회 재생성) → 저장
```

| 항목 | 내용 |
| --- | --- |
| 언제 | ① 채팅 `estimate` 경로 ② 견적서 줄 옆 '왜 이 금액?' 버튼(관문 생략) ③ 실측 견적서 도착 이벤트(worker, 미리 만들어 둠) ④ 추가 금액 기록 |
| 도구 | `get_standard()` · `get_range()` · `compare_quotes(trade)` · `search_knowledge(query, kind=estimate)` |
| 출력 `QuoteExplain` | `lead` · `line_notes[]{line_key, why}` · `range_why[]{driver, text}` · `bridge_notes[]{step, text}` · `missing[]{item, why}` · `ask_vendor[]` · `cited_keys[]` |
| 다루는 것 | 공공 기준 vs 시장 범위의 차이(T2: 공공 기준이 시장 보통가보다 높게 나오는 이유 — 철거 품 · 자재 소매가 · 합지 노무 구분 없음), 줄의 포함 상태 6종, 평당 견적의 함정, 부가세 별도, '일식', 실측 후 줄, 범위 밖 차이의 나머지 → 업체에 물을 질문 |
| 금지 | 차액 · 평당가 직접 계산(엔진이 파생 값까지 미리 넣음), 업체 탓 · 과장, 법률 판단 |
| 평가 | `quote_explanation` 시나리오(숫자 검사 100% · 누락 지적률 · 브리지 순서) |

## 7. 에이전트 사이 데이터 흐름 예

**"거실 몰딩 바꾸고 도배도 새로 하려는데 뭘 먼저 정해야 해요?"**
1. 관문: `both`(0.93)
2. 오케스트레이터: 목공 · 도배 서브 병렬, 각자 `get_brief` · `get_range` 1회씩
3. 목공: 질문 `molding_style` · `molding_len`, 주의 "몰딩이 끝나야 도배"
4. 도배: 질문 `ceiling` · `existing`, 주의 "목공 뒤 시공 · 바탕 확인"
5. 합치기(코드): "목공을 먼저 하고 도배를 해요. 4가지만 알려 주세요." + 질문 4개 카드(현재 목업 `BOTH` 장면과 같은 모양)
6. 고객 답 → chat.service가 브리프 저장 → 범위 다시 계산 → "범위가 ⟦before⟧ → ⟦after⟧로 줄었어요"
